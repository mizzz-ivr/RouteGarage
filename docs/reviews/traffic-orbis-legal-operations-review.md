# 交通情報・オービス情報の法務・運用レビュー（Issue #93）

- ドキュメント種別: 要件定義〜基本設計前フェーズのレビュー記録
- 対象Issue: https://github.com/mizzz-dev/RouteGarage/issues/93
- 関連Issue: Issue #89、Issue #91
- 関連PR: PR #90、PR #92
- 確認日: 2026-07-23
- AI利用: Codex / ChatGPT支援、人間レビュー必須
- 位置付け: 法的助言・適法性の最終判断ではない

## 1. 目的

交通情報・事故情報・PA閉鎖情報・オービス情報について、Repositoryの既存要件と公的機関・公式提供元の一次資料を照合し、後続設計へ進むための判断ゲートを整理する。

本レビューでは、各事項を次の4区分で扱う。

1. **確定要件**: 現時点のRepository要件と公的資料から、MVPの必須制約として固定できる。
2. **条件付き許容候補**: 利用条件、表示条件、運用責任者承認等を満たす場合のみ後続検討できる。
3. **MVP禁止**: 安全性・権利・運用上のリスクが高く、MVPでは実装しない。
4. **要専門確認**: 公的資料だけでは一律判断できず、法務・警察・データ提供元・ストア審査等への確認が必要。

## 2. 対象範囲

- 走行中の画面注視・操作
- 交通情報の正確性、完全性、更新遅延、欠落、競合
- オービス・速度取締り関連情報の表示目的、粒度、通知
- 固定式、移動式、ユーザー投稿型情報の差異
- 地域・路線・警察署単位の運用差
- データ提供元の利用規約、再配布、加工、キャッシュ、帰属
- 取得失敗、誤情報、規約変更、契約停止時の縮退運用
- 問い合わせ、訂正、通報、監査、エスカレーション

## 3. 非対象範囲

- 個別機能の適法性に関する最終判断
- データ提供元の採用決定
- 料金、契約、SLAの確定
- 表示距離、通知距離、鮮度閾値等の具体数値
- DB、API、認証、インフラ、監視の設計
- Next.js / Expoの実装
- ネイティブアプリのストア申請判断

## 5. Source of Truthとの照合結果

### 5.1 走行中の画面注視・操作

**判定: 確定要件**

- 走行中の入力、投稿、訂正、通報、再読込、フィルター変更、詳細確認を前提にしない。
- 操作が必要な場合は、安全な場所に停車してから行う文言を固定表示する。
- 走行中か不明な場合は、操作可能と推測せず制限側に倒す。
- 通知をタップして詳細確認させる導線、繰り返し画面を注視させる導線を採用しない。
- 走行中の画面注視を防げない機能は、表示内容が安全運転目的であっても採用しない。

Repositoryの`driving-safety-ui-policy.md`およびFR-MAP-03、NFR-SAFE-01〜02と整合している。

### 5.2 交通情報の正確性・完全性

**判定: 確定要件**

- 公式情報であることと、常に完全・最新であることを同一視しない。
- 提供元最終更新時刻、鮮度状態、検証状態、情報限界を利用者が確認できるようにする。
- RouteGarage受信時刻を提供元最終更新時刻の代替にしない。
- 既知の不一致が1件でもある情報は`競合`とし、通常表示候補にしない。
- 取得失敗、権利不明、完全性懸念、安全判断不能時は`提供停止`を優先する。

### 5.3 JARTICウェブサイトコンテンツの利用

**判定: MVP禁止**

- JARTICの一般公開ウェブページをスクレイピングし、地図・画像・テキストをRouteGarageで再表示する前提を置かない。
- ウェブサイト上のコンテンツを、無断で第三者表示、公衆送信、転載、改変、類似サービスへ流用しない。
- JARTIC名称・ロゴ・地図表示を、提供条件確認なしに利用しない。

**条件付き許容候補**

- JARTICが個別に提供するオープンデータまたは契約データは、当該データ固有の利用条件を確認した場合に限り候補とする。
- ウェブサイト利用規約と、オープンデータ・API・契約データの提供条件を混同しない。

### 5.4 オービス情報の利用目的

**判定: 確定要件**

- 目的は速度遵守・安全運転の注意喚起に限定する。
- 「ここだけ減速」「取締りを避ける」「この地点以外は安全」等の回避を示唆する表現を禁止する。
- 取締り地点を避けるルート最適化、回避実績のランキング・バッジ・ゲーム化を禁止する。
- 実際の制限速度を超える速度を推奨・許容しない。
- 取締りの有無にかかわらず法定速度・交通ルールを守る旨を固定表示する。

### 5.5 オービス表示粒度

| 表示案 | 判定 | 条件・理由 |
| --- | --- | --- |
| 法定速度・安全運転の一般的注意 | 確定要件として許容 | 取締り回避を目的にせず、走行中注視を促さないこと |
| 地域・路線単位の粗い注意表示 | 条件付き許容候補 | 情報源、基準日、鮮度、検証状態、権利確認、利用者注意を必須とする |
| 固定式設備の正確な座標表示 | 要専門確認 | 一律の適法性を裏付ける一次資料を本レビューでは確認できていない。提供元権利、表示目的、文言、地域運用、ストア審査を確認するまでMVPでは採用しない |
| 移動式取締りの現在位置・リアルタイム表示 | MVP禁止 | 未確認情報の即時拡散、取締り回避、誤情報、投稿者位置・時刻のプライバシーリスクが高い |
| ユーザー投稿による正確地点共有 | MVP禁止 | 検証、通報、削除、位置プライバシー、悪用防止、権利確認の要件が未確定 |
| 取締り地点を避けるルート提案 | MVP禁止 | 取締り回避支援と解釈されるリスクが高い |

### 5.6 通知・音声案内

| 通知案 | 判定 | 条件・理由 |
| --- | --- | --- |
| 安全運転の一般的な事前注意 | 条件付き許容候補 | 走行前または停車中に確認する設計、頻度制限、内容固定、取締り地点との直接紐付けを避ける |
| 走行中のプッシュ通知・画面ポップアップ | MVP禁止 | 画面注視・タップ操作を誘発するため |
| 正確地点接近時の音声通知 | 要専門確認・MVP未採用 | 法務、走行安全UI、提供元、ストア審査、誤通知時運用を確認できるまで採用しない |
| 移動式取締り・警察位置のリアルタイム通知 | MVP禁止 | 取締り回避、誤情報、悪用、地域運用差のリスクが高い |
| 取得失敗・提供停止通知 | 条件付き許容候補 | 運転操作を求めず、情報を利用できないことだけを簡潔に伝える。詳細操作は停車後に限定 |

### 5.7 地域差

**判定: 確定要件**

- 都道府県・警察署単位で事故実態や重点路線等に応じた速度取締り指針が策定されるため、取締り運用を全国一律と断定しない。
- 公表された重点路線・時間帯は、取締りが当該範囲だけに限定されることを保証しない。
- 地域別データを扱う場合は、対象地域、基準日、発表主体、正式発表状態を保持する。
- 地域差を理由に「この地域・路線では取締りがない」と表示しない。

**要専門確認**

- 地域別条例・公安委員会規則が表示・通知仕様へ与える影響。
- 都道府県警察の公表情報をアプリへ転載・加工・通知することの可否。
- 全国展開時の地域別問い合わせ・訂正・停止窓口。

## 6. MVP判断マトリクス

| 項目 | MVP判断 | 後続ゲート |

| 交通情報の参考表示 | 条件付き許容候補 | 正式な提供条件、更新時刻、鮮度、検証、停止運用を確定 |
| 一般的な安全運転注意 | 確定要件として許容 | 固定文言、人間レビュー、走行中操作を誘発しないこと |
| 地域・路線単位のオービス注意 | 条件付き許容候補 | 法務・提供元・地域運用レビュー |

| オービス接近通知 | 要専門確認・MVP未採用 | 法務・安全UI・誤通知運用・地域差レビュー |

| 提供条件確認済みオープンデータ | 条件付き許容候補 | 個別ライセンス、再配布、加工、キャッシュ、帰属確認 |

## 7. データ提供元採用前の法務・運用チェック

採用候補ごとに、IssueまたはADRで以下を記録する。

- 提供主体と上流作成主体
- 正式発表、事業者一次観測、ユーザー投稿、派生・推定の分類
- 契約・利用規約の名称、版、確認日、確認者
- 商用利用、第三者表示、公衆送信、再配布の可否
- データ加工、派生データ作成、他情報との統合可否
- キャッシュ保存、再表示、有効期限、削除義務
- 必須の帰属、ロゴ、リンク、著作権表示
- 提供元最終更新時刻の有無
- 更新頻度、遅延、欠落、訂正、撤回通知の仕様
- 対象地域と地域別制限
- 固定式、移動式、投稿型、予測型等の情報種別
- 検証方法と競合時の優先規則
- 規約変更・契約停止時の停止手順
- 問い合わせ・監査時に根拠を提示できること

1項目でも判断不能で、安全な表示可否を判断できない場合は採用しない。

## 8. 運用要件

### 8.1 提供停止

- 規約変更、契約停止、権利不明、更新時刻不明、期限切れ、完全性懸念、安全判断不能時は、必ず`提供停止`とする。
- データ種別・地域・提供元単位で提供停止できる運用手順を後続設計で用意する。
- 提供停止中は推測値や別情報源からの自動補完を表示しない。

### 8.2 訂正・通報

- 利用者が誤情報、古い情報、権利侵害、危険な表現を通報できる導線を用意する。
- 事実確認前に正誤を断定しない。
- 安全影響が高い場合は調査完了前でも一時停止できること。
- 通報者の位置、時刻、識別子を必要以上に公開しない。

### 8.3 監査

最低限、次を追跡可能にする。

- 情報源、上流由来、調達経路
- 提供元更新時刻、受信時刻
- 表示可否、鮮度、検証状態と判定理由
- 表示文言・注意文言の版
- 制限表示・提供停止の承認者、時刻、根拠
- 通報、訂正、一時停止、復旧の履歴
- 規約・契約・法務レビューの版と確認者

### 8.4 定期レビュー

- 利用規約・提供条件変更を検知する責任者と確認周期を後続運用設計で決定する。
- 地域別指針・公表情報は基準日を保持し、古い情報を現在の運用として断定しない。
- 重大事故、苦情、誤通知、権利者指摘が発生した場合は、定期周期を待たず再レビューする。

## 9. 要専門確認事項

### 9.1 法務・警察等への確認

- 正確な固定式設備座標を安全運転目的で表示する場合の法的・運用上の留意点
- 位置接近通知・音声通知の可否と、取締り回避目的と評価されないための条件
- 移動式・公開取締り情報を扱うことの可否
- 都道府県公安委員会規則・地域運用差が表示仕様へ与える影響
- 警察・道路管理者の公表資料の転載、加工、通知利用の可否

### 9.2 データ提供元への確認

- 再配布、公衆送信、画面表示、通知への利用可否
- 正確な座標・画像・名称の表示可否
- キャッシュ、加工、統合、派生データ作成の可否
- 最終更新時刻、訂正、撤回、停止通知の提供有無
- 地域別・情報種別ごとの利用制限

### 9.3 運用責任者への確認

- 制限表示・キャッシュ表示の承認者
- 緊急停止・復旧判断者
- 通報・訂正・事故・苦情のSLA
- 夜間・休日の停止判断体制
- 監査ログの閲覧権限・保持期間

### 9.4 ストア審査への確認

ネイティブアプリはMVP対象外だが、将来対応時はApp Store / Google Playの最新審査要件を別Issueで確認する。

## 10. Go / No-Goゲート

以下を全て満たすまで、交通情報・オービス情報の実装Issueへ進まない。

1. 採用候補データの利用条件を確認済み。
2. 表示粒度・通知方法が法務・安全・提供元レビューで承認済み。
3. 利用者向け注意文言が人間レビュー済み。
4. 提供停止・訂正・通報・監査の責任者と手順が定義済み。
5. 鮮度・検証・競合・キャッシュの判定基準が情報種別ごとに定義済み。
6. 地域差を断定せず、対象地域と基準日を管理できる。
7. AI生成要件を人間がレビュー済み。

1項目でも未完了の場合はNo-Goとする。

## 11. 本レビューで確定しない事項

- 正確座標表示の採用可否
- 通知・音声案内の採用可否
- 採用するデータ提供元
- 具体的な通知距離・頻度・鮮度閾値
- 法務・ストア審査の最終判断
- 地域別仕様の詳細
- 実装アーキテクチャ

## 12. 後続Issue候補

1. データ提供元候補の利用条件・上流由来・再提供経路比較
2. 交通情報・オービス情報の表示粒度と利用者向け文言の画面詳細設計
3. 提供停止・訂正・通報・監査の運用設計
4. 法務・データ提供元への確認結果反映
5. ネイティブアプリ対応時のストア審査レビュー

## 13. 受け入れ条件

- 公的資料・公式規約とRepository要件の対応が説明できる。
- 確定要件、条件付き許容候補、MVP禁止、要専門確認が区分されている。
- 表示粒度、通知、地域差の判断マトリクスがある。
- 取締り回避・危険運転を助長する機能が禁止されている。
- 走行中注視・操作を助長しない。
- JARTICウェブページの無断転載・再配布・改変を前提にしていない。
- データ提供元採用前チェックが定義されている。
- 提供停止・訂正・通報・監査要件が定義されている。
- 法務・提供元・運用責任者への確認事項がある。
- 未確定事項を断定していない。
- 実装コード・技術選定変更がない。
- AI生成内容の人間レビューが必須である。
