# 交通情報データ提供元候補比較（Issue #97）

- ドキュメント種別: 要件定義〜基本設計前フェーズの比較・調査記録
- 対象Issue: https://github.com/mizzz-ivr/RouteGarage/issues/97
- 関連Issue: Issue #89、Issue #91、Issue #93
- 関連PR: PR #90、PR #92、PR #96
- 確認日: 2026-07-23
- AI利用: Codex / ChatGPT支援、人間レビュー必須
- 位置付け: 採用決定、契約判断、法的助言ではない

## 1. 目的

交通情報の画面詳細設計、API設計、データモデル設計へ進む前に、データ提供元候補について次を比較し、Go / No-Go判断に必要な確認事項を明確にする。

- 提供主体と契約主体
- 上流由来と調達経路
- 日本国内の対象地域・情報種別
- 商用利用、第三者表示、公衆送信、再配布
- 加工、統合、派生データ作成
- キャッシュ、保存、有効期限、削除義務
- 帰属、ロゴ、リンク、著作権表示
- 更新時刻、遅延、欠落、訂正、撤回
- 規約変更、契約停止、障害時の提供停止
- 監査・問い合わせ時に必要な証跡

本比較は候補を採用するものではない。公開資料で確認できない事項は推測せず、`要問い合わせ`または`現時点No-Go`とする。

## 2. 前提となるRepository要件

候補にかかわらず、`docs/policies/traffic-and-orbis-information-policy.md`および`docs/reviews/traffic-orbis-legal-operations-review.md`の要件を維持する。

- 公式情報であることと、完全・最新であることを同一視しない。
- 上流由来、調達経路、再提供経路を追跡可能にする。
- 提供元最終更新時刻をRouteGarage受信時刻で代替しない。
- 権利・契約・上流由来・必須メタデータを確認できない場合は`提供停止`とする。
- キャッシュ再表示は契約上許可され、提供元最終更新時刻と有効期限を確認できる場合に限る。
- 走行中の入力、詳細確認、視覚・タップ操作を誘発する能動通知を前提にしない。
- 移動式取締り・警察位置のリアルタイム情報を候補に含めない。
- 取締り回避を目的とする表示、通知、ルート提案を行わない。
- 判断不能時はNo-Goとする。

## 3. 比較ステータス

| ステータス | 意味 |
| --- | --- |
| 用途限定候補 | 公開資料から利用可能な用途を確認できるが、用途・鮮度・表示方法を限定する必要がある |
| 優先問い合わせ候補 | RouteGarage要件との適合可能性があるが、公開資料だけでは契約・再提供条件を確定できない |
| 構成依存候補 | 特定の地図・ルート基盤と一体でのみ検討でき、提供元中立のデータ基盤用途には使えない |
| 現時点No-Go | 対象地域、権利、契約、再提供条件等を確認できず、現時点では設計前提にできない |
| 非対象 | RouteGarageのMVP要件または安全方針により候補から除外する |

## 5. 候補別確認結果

### 5.1 JARTICオープンデータ

#### 公式資料

- 各種情報の提供（オープンデータ）
  - https://www.jartic.or.jp/service/opendata/
- オープンデータ利用規約
  - https://www.jartic.or.jp/d/opendata/riyou_kiyaku.pdf

#### 確認できた事項

- 対象は交通規制情報、断面交通量情報、国土交通省交通量データ、交差点制御情報である。
- 原則として毎月月初に更新され、更新前の情報は取得できなくなる。
- 複製、公衆送信、翻案・変形等を含む利用と商用利用が可能である。
- 出典表示が必要である。
- 編集・加工した場合は加工した事実を表示し、JARTICまたは国・府省等が作成したように表示してはならない。
- 第三者の権利が含まれる場合は利用者の責任で確認・許諾取得が必要である。
- データは予告なく変更、移転、削除される場合がある。
- 規約はCC BY 4.0と互換性がある。

#### RouteGarageでの扱い

`用途限定候補`とする。

- 交通規制、交通量、交差点制御等の静的・定期更新データとして検討できる。
- 月次更新のため、現在の渋滞、事故、閉鎖、所要時間を示すリアルタイム交通情報として扱わない。
- 利用時点、データ対象期間、提供元更新日、RouteGarage受信時刻を分けて保持する。
- 加工時は出典と加工表示を必須にする。
- 第三者権利を確認できない項目は表示しない。
- 更新前データが取得不能になるため、必要な保存可否と履歴保持方針を人間レビューで確認する。

### 5.2 JARTIC Jシステム / VICS符号型

#### 公式資料

- JARTIC 法人向け情報提供サービス「Jシステム」
  - https://www.jartic.or.jp/s/service/forcorporation/forcorporation01/
- VICSセンター「事業者への情報提供」
  - https://www.vics.or.jp/center/offering/

#### 確認できた事項

- JARTICは民間の情報提供事業者へ道路交通情報をオンライン提供している。
- 渋滞、事故・工事等の規制、所要時間、都市高速入口出口閉鎖、SA・PA、駐車場、工事予定、冬期閉鎖等が提供対象である。
- テキスト型、簡易図型、VICS符号型がある。
- 基本は5分更新で、高速道路等の一部メニューでは1分更新がある。
- 高速道路は全国9エリア、一般道路は47都道府県の提供メニューがある。
- 開始時負担額、月額基本額、型式・利用者・エリア別負担額が公開されている。
- VICS符号型の利用にはVICSセンターとの技術開示契約と別途技術開示料が必要である。
- VICSセンターはJARTICからの委託によりVICS符号型情報を事業者へ提供している。

#### 公開資料だけでは確認できない事項

- RouteGarage利用者への表示・公衆送信の具体的許諾範囲
- RouteGarageサーバーでのキャッシュ可否、保存期間、削除義務
- 生データまたは加工データの再配布可否
- 他社地図への重畳条件
- 必須の帰属、ロゴ、リンク、権利表示
- 提供元更新時刻・訂正・撤回・無効化通知のフィールド仕様
- SLA、障害通知、サポート、契約停止時の処理
- RouteGarageから委託先・関連サービスへ再提供する場合の条件

#### RouteGarageでの扱い

`優先問い合わせ候補`とする。

国内のライブ交通情報候補として、JARTICデジタル事業推進部へ以下を問い合わせるまで採用しない。

1. RouteGarageのWeb・モバイル利用者への表示可否
2. 商用サービスでの利用区分と負担額計算
3. テキスト型・簡易図型・VICS符号型の選定条件
4. キャッシュ、再表示、履歴保存、バックアップの許可範囲
5. 加工・統合・他社地図重畳・派生情報作成の許可範囲
6. 上流由来、提供元更新時刻、訂正・撤回通知の取得可否
7. 帰属、ロゴ、リンク、利用者向け注意表示
8. 契約停止、規約変更、障害時の提供停止手順
9. 監査ログと委託先利用に必要な条件
10. VICS技術開示契約が必要となる構成

### 5.3 Google Maps Platform Routes API

#### 公式資料

- Routes API 交通オプション
  - https://developers.google.com/maps/documentation/routes/traffic-opt
- Google Maps Platform Terms of Service
  - https://cloud.google.com/maps-platform/terms

#### 確認できた事項

- Routes APIは交通情報をルート選択と推定所要時間へ反映できる。
- 交通状況を含むポリライン等のオプションがある。
- Google Mapsコンテンツのスクレイピング、サービス外への保存、再共有、再ホストは禁止される。
- 個別サービス条件で明示される場合を除き、キャッシュは禁止される。
- Google Mapsコンテンツから派生コンテンツを作成してはならない。
- Google Maps Core Servicesを非Google地図と同一アプリ内で併用することに制限がある。
- エンドユーザー向け利用規約・プライバシーポリシーへの告知と帰属表示が必要である。
- 位置情報の取得・キャッシュには、事前かつ撤回可能な明示的同意が必要である。

#### RouteGarageでの扱い

`構成依存候補`とする。

- Google Mapsを地図・ルート基盤として採用し、Googleのレスポンスを許可された範囲で即時表示する構成でのみ検討する。
- 提供元中立の交通情報データベース、長期履歴、他社地図への重畳、複数利用者への再配布用途には採用しない。
- Googleのルート結果を交通情報の生データまたは独自交通データセットへ変換しない。
- Google Maps Platform採用判断と同時に、Service Specific Terms、表示方式、キャッシュ、帰属、利用者同意を再確認する。
- 地図基盤未決定の現段階では採用候補順位を確定しない。

### 5.4 HERE Traffic API v7

#### 公式資料

- HERE Traffic API v7概要
  - https://docs.here.com/traffic-api/ja/v1.0/docs/introduction-to-here-traffic-api-v7
- HERE Traffic API v7カバレッジ
  - https://docs.here.com/traffic-api/docs/traffic-here-traffic-api-v7-coverage-information
- HERE Platform Terms / Acceptable Use Policy
  - https://legal.here.com/us-en/terms
  - https://legal.here.com/en-gb/terms/acceptable-use-policy-2018

#### 確認できた事項

- リアルタイムの交通流とインシデント情報をREST APIで提供する。
- JSONの速度、渋滞要素、道路セグメント形状、インシデント種別・場所・状態・期間等を扱う。
- 公式カバレッジ表に日本のFlowとIncidentsが掲載されている。
- HEREの公開利用条件では、位置データのリポジトリ構築や1回の取得結果を複数利用者へ使い回す目的のキャッシュが制限される。
- HTTPキャッシュヘッダーで許可される場合等を除き、事前取得・保存に制限がある。
- HERE由来情報と第三者情報を組み合わせる場合、由来を区別し帰属表示を維持する必要がある。
- 別契約またはプラン固有条件が一般条件を変更する場合がある。

#### 公開資料だけでは確認できない事項

- RouteGarageの想定利用者数・構成に適用される契約プラン
- Traffic APIレスポンスのサーバー側キャッシュと複数利用者表示の具体条件
- 他社地図への重畳、加工、派生状態判定の許可範囲
- 生データ・加工データの再配布可否
- 日本向けデータの上流由来と提供元更新時刻の詳細
- SLA、訂正、撤回、障害通知、契約停止時の削除義務
- 必須のサプライヤー表記と利用者向け契約条項

#### RouteGarageでの扱い

`優先問い合わせ候補`とする。

- 日本のFlow / IncidentsをAPI経由で都度表示する構成候補として技術・契約確認を進める。
- 提供元中立の永続データベースや無期限履歴保存を前提にしない。
- 1リクエストを複数利用者へ使い回すキャッシュを前提に見積もらない。
- HERE営業・法務へ、RouteGarageのWeb・モバイル構成、利用者数、地図基盤、キャッシュ、加工、帰属、再提供を提示して確認する。

### 5.5 TomTom Traffic API

#### 公式資料

- Traffic API概要
  - https://docs.tomtom.com/traffic-api/documentation/tomtom-maps/v1/product-information/introduction
- Traffic API Market Coverage
  - https://docs.tomtom.com/traffic-api/documentation/tomtom-maps/v1/product-information/market-coverage
- Pricing
  - https://developer.tomtom.com/pricing
- Terms and conditions
  - https://docs.tomtom.com/legal/terms-and-conditions

#### 確認できた事項

- Traffic FlowとTraffic IncidentsのAPIを提供している。
- Traffic Incidentサービスは1分更新と案内されている。
- セルフサービス・従量課金・Enterprise契約の導線があり、商用アプリ利用可能と案内されている。
- APIレスポンスのキャッシュ可否はエンドポイントのCache-Controlに従う必要がある。
- 公開されているTraffic API Market Coverageは2022-11-14更新で、アジア一覧に日本が掲載されていない。
- 別製品のTraffic Statsには日本が掲載されているが、Traffic APIの現在提供を示す根拠にはしない。

#### RouteGarageでの扱い

`現時点No-Go`とする。

これは永久除外ではなく、次の確認が完了するまで設計前提にしないという意味である。

1. 現行Traffic Flow / Incidents APIの日本提供可否
2. 日本向けデータの対象道路・地域・品質・更新頻度
3. 適用される最新契約条件と料金プラン
4. Web・モバイル利用者への表示、公衆送信、再提供条件
5. キャッシュ、保存、履歴、加工、他社地図重畳条件
6. 帰属、エンドユーザー条項、プライバシー条件
7. 上流由来、訂正、撤回、SLA、契約停止時の処理

公式Traffic APIカバレッジが更新されるか、TomTomから書面回答を得た場合に再評価する。

## 6. 上流由来・再提供経路

| 候補 | 公開資料から確認できる経路 | RouteGarageで必要な追加確認 |
| --- | --- | --- |
| JARTICオープンデータ | 国・府省・JARTIC等のデータ → JARTIC公開CSV → RouteGarage | データ項目別の第三者権利、保存・履歴方針、更新・削除検知 |
| JARTIC Jシステム | 道路交通情報の上流機関 → JARTIC → 契約事業者 → RouteGarage利用者 | 上流機関識別子、再提供許諾、加工・キャッシュ、帰属、SLA |
| VICS符号型 | JARTIC → VICSセンター（JARTIC委託） → 技術開示契約事業者 → RouteGarage利用者 | JARTIC契約とVICS技術開示契約の責務分界、地図重畳・再提供条件 |
| Google Routes API | Googleが提供する交通対応ルートサービス → RouteGarageアプリ内表示 | 個別上流由来は公開資料だけで確定せず、Googleコンテンツとして契約条件に従う |
| HERE Traffic API | HEREが集約・提供するFlow / Incidents → API → RouteGarageアプリ内表示 | 日本データの上流由来、サプライヤー表記、複数利用者表示・キャッシュ条件 |
| TomTom Traffic API | TomTomが提供するFlow / Incidents → API → RouteGarageアプリ内表示 | 日本提供可否、上流由来、契約・表示・再提供条件の全てを再確認 |

上流由来を確認できない候補は、事業者名が明確でもRepository上の`上流由来不明`として扱い、表示可能としない。

## 7. Go / No-Goゲート

候補を基本設計へ進めるには、以下をすべて満たす必要がある。

1. 契約主体と適用規約・契約書の版を特定できる。
2. 日本国内の対象地域・道路・情報種別を確認できる。
3. RouteGarage利用者への表示、公衆送信、第三者提供が許可される。
4. 他社地図への重畳可否を確認できる。
5. 加工、統合、派生状態判定の許可範囲を確認できる。
6. キャッシュ、保存期間、有効期限、削除義務を確認できる。
7. 提供元最終更新時刻、受信時刻、訂正、撤回を追跡できる。
8. 帰属、ロゴ、リンク、サプライヤー表記を実装可能である。
9. 規約変更、契約停止、障害時に提供元・地域・情報種別単位で停止できる。
10. 監査、問い合わせ、苦情、誤情報対応に必要な証跡を保持できる。
11. 位置情報やプローブデータの利用について、利用者同意とプライバシー要件を満たせる。
12. 走行安全・取締り回避防止の既存要件を弱めない。
13. 法務・運用責任者・人間レビュー担当者が承認する。

1項目でも判断不能で安全な表示可否を確認できない場合はNo-Goとする。

## 8. 推奨する問い合わせ順序

採用順位ではなく、不確実性を解消する順序として次を推奨する。

1. **JARTIC Jシステム / VICS**
   - 国内リアルタイム交通情報の契約・再提供・更新時刻・停止条件を確認する。
2. **HERE Traffic API**
   - 日本カバレッジが確認できる商用APIとして、キャッシュ・加工・他社地図重畳・再提供条件を確認する。
3. **Google Maps Platform**
   - 地図基盤をGoogleへ統一する案を採用候補にする場合のみ、Routes API固有条件を確認する。
4. **TomTom Traffic API**
   - 現行の日本提供可否を書面確認してから比較へ戻す。

JARTICオープンデータは上記問い合わせと並行して、静的・定期更新データ用途に限定したデータ項目レビューを行う。

## 9. Rejected Alternatives

- JARTIC一般ウェブページをスクレイピングして再表示する案
  - 一般サイト規約と個別提供データ条件を混同するため不採用。
- Google Routes APIの結果を独自交通データセットとして保存・再配布する案
  - Google Mapsコンテンツの保存、再共有、派生利用制限と整合しないため不採用。
- HEREまたはTomTomのAPIレスポンスを契約確認なしに長期保存し、複数利用者へ再利用する案
  - 公開条件から許諾を確認できないため不採用。
- Traffic Statsに日本があることを理由にTomTom Traffic APIも日本対応と推測する案
  - 製品が異なり、Traffic APIの根拠にならないため不採用。
- APIが利用可能であることを再配布・加工・商用利用の包括許諾とみなす案
  - 利用可能性と権利範囲は別事項のため不採用。
- オービス・移動式取締り・警察位置のリアルタイムデータを同時に選定する案

- 地図基盤と交通データの併用制限を見落とすこと。
