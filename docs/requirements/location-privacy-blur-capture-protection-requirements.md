# 生活拠点ぼかし・共有出力・外部キャプチャ保護要件（Issue #119）

- 対象Issue: https://github.com/mizzz-ivr/RouteGarage/issues/119
- 作成日: 2026-07-31
- フェーズ: Phase 1 / Requirements Definition
- 状態: 要件ドラフト / 人間・法務・運用・安全・セキュリティ・プライバシー・アクセシビリティレビュー必須
- 実装状態: 未実装
- AI利用: ChatGPT支援。AI生成物は人間レビュー必須
- 位置付け: 法的助言、プライバシー影響評価の最終結論、アルゴリズム設計、OS保証、実装仕様ではない

## 1. 目的

RouteGarageが扱う位置情報・走行履歴について、利用者の自宅、職場、生活圏、反復訪問地点、開始・終了地点等を第三者が推定するリスクを低減するため、通常表示、公開、共有、印刷、エクスポート、外部キャプチャに適用する要件とGo / No-Goゲートを定義する。

本書では、ぼかし距離・時間閾値・クラスタリング条件等の具体値や、特定ライブラリ・OS機能の採用を決定しない。具体値は、実データを公開Repositoryへ保存せず、承認済みの匿名・合成テストデータとプライバシー評価に基づく後続設計で決定する。

## 3. 公式資料の確認

確認日: 2026-07-31

### 3.1 Expo ScreenCapture

- https://docs.expo.dev/versions/latest/sdk/screen-capture/

確認事項:

- `expo-screen-capture`はAndroid / iOSでスクリーンショット・画面収録の抑止候補を提供する。
- スクリーンショット検知とキャプチャ抑止は別機能である。
- Androidではキャプチャ検知の権限要件がOSバージョンで異なる。
- iOS向けにアプリスイッチャー・バックグラウンドスナップショットをぼかす機能候補がある。
- APIが利用可能であることと、全OS・全端末・全ミラーリング・全外部撮影経路を完全に防げることは同義ではない。
- Expo / React Native採用、ライブラリ導入、バージョン固定は本Issueでは決定しない。

### 3.2 Android

- https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE

確認事項:

- `FLAG_SECURE`は、対象Windowをスクリーンショットや非セキュアディスプレイへ表示しないための候補である。
- OS機能の存在だけで、端末固有挙動、外部カメラ撮影、将来OS、全画面共有経路まで保証されたとは扱わない。
- 実装候補とする場合は、対象OS・端末・画面状態・マルチウィンドウ・バックグラウンドを含む実機検証を必須とする。

### 3.3 iOS

- https://developer.apple.com/documentation/uikit/uiscenecapturestate
- https://developer.apple.com/documentation/uikit/uiscreen/captureddidchangenotification

確認事項:

- sceneのキャプチャ状態から、画面が録画・ミラーリング中かを判定する候補がある。
- 旧`UIScreen.isCaptured`は非推奨であり、後続設計時に最新APIを再確認する。
- キャプチャ状態の検知は、キャプチャ開始前に内容流出を必ず防ぐ保証ではない。
- スクリーンショット後の通知だけを事前保護として扱わない。

### 3.4 Web印刷

- https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Printing

確認事項:

- `@media print`、印刷専用スタイルシート、`beforeprint` / `afterprint`により印刷時表示を変更できる。
- 印刷CSSはブラウザ印刷・PDF保存の安全化候補であり、OSスクリーンショット・画面収録の防止機能ではない。
- 対象ブラウザ、印刷プレビュー、PDF保存、システムダイアログ差を検証する。

公式資料は後続設計・実装開始前、およびリリース前に再確認する。

## 4. 基本原則

1. **通常表示安全化**: 外部キャプチャを完全に防げない環境では、通常表示自体をプライバシーセーフにする。
2. **非公開初期値**: 位置情報・走行履歴の公開初期値を非公開または限定公開とする。
3. **精密座標非公開**: 公開・共有・印刷・一般エクスポートへ正確な開始・終了・生活拠点候補を含めない。
4. **再推定対策**: 点の座標だけでなく、道路形状、端点、時刻、反復、複数記録の組合せからの再推定を評価する。
5. **処理失敗時No-Go**: ぼかし・マスク・プレビュー・保護状態のいずれかが失敗・不明なら公開・共有・印刷・エクスポートを停止する。
6. **検知と抑止の分離**: スクリーンショット検知、録画状態検知、キャプチャ抑止、アプリスイッチャー保護を別能力として管理する。
7. **注意文依存禁止**: `共有しないでください`、`スクリーンショット禁止`等の注意文だけで安全要件を満たしたと扱わない。
8. **プレビュー一致**: 共有前プレビューと実際の出力物に同じプライバシー変換を適用する。
9. **帰属維持**: Google Maps、JARTIC、RouteGarage加工表示等の必須帰属をぼかし処理で欠落させない。
10. **最小監査**: 監査記録へ精密座標、走行軌跡、生活拠点候補値、出力画像本体を不要に保存しない。
11. **設定で安全を解除しない**: 利用者設定だけで、組織が定めた最低プライバシー保護を下回らせない。
12. **判断不能時No-Go**: 地点分類、再推定リスク、保護能力、出力結果を判断できない場合は公開しない。

## 5. 用語

| 用語 | 定義 |
| --- | --- |
| 機微地点 | 公開により自宅、職場、生活圏、個人行動を推定され得る地点 |
| 生活拠点候補 | 反復訪問、長時間滞在、開始終了頻度等から自宅・職場等と推定され得る地点 |
| 機微パターン | 単独座標ではなく、経路形状、時系列、反復、複数記録の重なりから個人を推定できる特徴 |
| プライバシー変換 | 除去、切り詰め、粗粒度化、集約、非表示等により公開精度を下げる処理 |
| プライバシーセーフ表示 | 承認済み変換と固定注意を適用し、機微地点・機微パターンを公開しない表示 |
| アプリ内出力 | RouteGarageの共有画像、印刷用表示、公開URL、エクスポート処理を経由した出力 |
| 外部キャプチャ | OSスクリーンショット、画面収録、ミラーリング、AirPlay、画面共有、ブラウザ印刷、外部カメラ撮影等 |
| 再推定 | ぼかし後データや複数情報から元の生活拠点・位置・行動を推測すること |
| 最低保護基準 | 利用者が設定で解除できない、RouteGarage共通の必須プライバシー保護 |

## 6. 位置情報の分類

位置情報は、少なくとも次の4分類を独立して扱う。

| 分類 | 例 | 通常公開 | 一般共有・印刷・エクスポート |
| --- | --- | --- | --- |
| `EXACT_PRIVATE` | 正確な現在位置、原GPS、正確な開始終了地点、非公開走行軌跡 | No-Go | No-Go |
| `SENSITIVE_DERIVED` | 生活拠点候補、反復訪問地点、長時間滞在地点、推定職場、自宅候補 | No-Go | No-Go |
| `PRIVACY_REDUCED` | 承認済み変換後の経路・地域・地点 | 条件付き候補 | 条件付き候補 |
| `PUBLIC_NON_LOCATION` | 距離、日付の粗い表現、公開可能な説明等 | 候補 | 候補 |

分類不能な情報は`EXACT_PRIVATE`相当として扱う。

`PRIVACY_REDUCED`は、単に桁を丸めた、円を重ねた、座標表示を隠しただけでは成立しない。道路形状や他記録との組合せを含む再推定評価が必要である。

## 7. 機微地点・機微パターン

### 7.1 機微地点候補

- 走行開始地点
- 走行終了地点
- 同一利用者の反復開始・終了地点
- 長時間滞在地点
- 夜間・早朝の反復滞在地点
- 利用者が自宅・職場・非公開として指定した地点
- 非公開スポット・限定公開スポット
- 低頻度地域、私道、袋小路、単独施設等、粗い位置でも個人を推定しやすい地点
- 問い合わせ・削除要求・運用対応で一時的に扱う位置

利用者が明示指定していない地点も、行動パターンから機微地点候補になり得る。

### 7.2 機微パターン候補

- 複数走行記録で共通する端点
- ぼかし境界から続く道路が少なく、元地点を逆算できる形状
- 短距離走行で、経路の大部分が生活圏を示す状態
- 同じ曜日・時刻の反復移動
- 特定施設・駐車場・住宅地への反復進入
- 共有画像の表示中心、ズーム、地名、ランドマークから推定できる状態
- 画像EXIF、ファイル名、説明文、スポット名等との組合せ
- 複数公開記録の重ね合わせによりマスク範囲が狭まる状態

### 7.3 判定不能時

機微地点・機微パターンの判定が完了しない場合:

- 公開・共有・印刷・エクスポートを`PRIVACY_BLOCKED`とする。
- 非公開の本人閲覧でも、外部キャプチャ保護を保証できない画面はプライバシーセーフ表示へ制限する。
- 推測で`PRIVACY_REDUCED`へ昇格しない。

## 8. プライバシー変換の要件

### 8.1 変換候補

後続設計で、次の組合せを評価する。

- 機微地点周辺の経路除去
- 経路端点の切り詰め
- 一定範囲を超えるまで経路を非表示
- 地域・道路区分への粗粒度化
- 複数点の集約
- 公開用経路と本人用経路の分離
- 地名・施設名・ラベルの除去または粗粒度化
- 表示中心・ズームの安全な初期化
- 画像EXIF・位置メタデータの除去

無作為な座標移動・ジッターにより、実際に走行していない道路や危険な場所を走行したように見せる方式は、真正性・誤認リスクを別途評価し、承認なしに採用しない。

### 8.2 最低要件

- 正確な開始・終了地点を公開しない。
- マスク境界から一本道で元地点を容易に逆算できない。
- 1件だけでなく、同一利用者の複数公開記録を組み合わせて評価する。
- 地図の中心、ズーム、ラベル、地名、サムネイルから機微地点を推定できない。
- 非表示にした区間が、距離、所要時間、標高、説明文等から復元できないか確認する。
- 公開用データから原座標を復元できる内部ID・埋め込み値・メタデータを除外する。
- 変換後に経路の有用性が成立しない場合は、経路を公開せず概要情報だけを候補とする。

### 8.3 利用者指定と機械判定

- 利用者指定の機微地点は、機械判定結果より保護範囲を狭める目的に使用しない。
- 機械判定で追加検出した機微地点を利用者が無条件に解除できる設計にしない。
- 利用者は保護範囲を広げる候補、追加非公開地点の指定、公開中止を選択できる。
- 最低保護基準を下回る例外は、通常設定では提供しない。

## 9. ぼかし具体値の決定基準

距離、時間、訪問回数、滞在時間、ズーム等の具体値は本Issueで決定しない。後続設計では、最低限次を評価して決定する。

- 都市部、郊外、過疎地域の道路・建物密度
- 一本道、袋小路、私道、山間部等の道路トポロジー
- 1件の記録と複数記録を組み合わせた再推定成功率
- 共有画像の解像度、地図ズーム、表示ラベル
- 走行距離に対するマスク区間の割合
- 短距離走行で残る公開価値
- 公開範囲（本人、限定、公開、不特定多数）
- 反復訪問・時間帯・滞在傾向
- 位置情報とプロフィール・車両・画像・投稿文の組合せ
- 法務・プライバシー・安全レビュー結果
- 匿名・合成テストデータによる攻撃者視点評価

具体値の決定には、プロダクト責任者、プライバシー責任者、セキュリティ責任者、法務確認者の承認を必要とする。

再推定リスクを評価できない場合は、経路公開をNo-Goとする。

## 10. 表示・出力別要件

### 10.1 本人向け通常表示

- 非公開の本人向け画面であっても、外部キャプチャ可能性を前提とする。
- Webでは、スクリーンショット・画面収録を確実に抑止できる前提を置かない。
- 精密位置を表示する必要性、表示時間、表示範囲を最小化する。
- 外部キャプチャ保護がない画面で、正確な生活拠点候補と公開JARTICレイヤーを同時表示しない。
- 精密表示と公開用プレビューを視覚的・状態的に分離する。

### 10.2 公開走行記録・公開プロフィール

- `PRIVACY_REDUCED`だけを表示候補とする。
- 公開初期値は非公開または限定公開とする。
- 公開範囲変更には、プライバシー変換済みプレビューと明示確認を必須とする。
- 複数記録を一覧・地図へ重ねる場合、横断的な再推定評価を行う。

### 10.3 アプリ内共有画像

共有前プレビューで次を確認できること。

- 公開される経路・地点・地名
- マスクされた開始・終了・生活拠点候補
- 公開範囲
- 画像の表示中心・ズーム
- 対象日・対象年月の公開粒度
- JARTIC・Google Maps等の必要帰属
- RouteGarage加工表示
- ぼかし後も推定リスクがゼロではない旨

プレビューと実出力で、同じ変換版、データ版、帰属版、描画条件を使用する。

### 10.4 URL共有・埋め込み

- URLを知る者だけの共有を、技術的な非公開保証として扱わない。
- 検索インデックス、OGP、サムネイル、埋め込みプレビュー、キャッシュへ機微情報を含めない。
- 公開範囲変更・削除・権利失効時に、共有表示・OGP・キャッシュを停止・無効化できる要件を持つ。
- URLパラメータ、HTML、クライアントデータへ原座標を埋め込まない。

### 10.5 ブラウザ印刷・PDF保存

- 印刷専用レンダリングまたは`@media print`で、正確な現在位置、原走行軌跡、開始終了地点、生活拠点候補、非公開注釈を除外する。
- 印刷プレビューとPDF保存結果の両方を検証する。
- JavaScriptイベントだけに依存せず、印刷CSSで安全側の初期状態を持つ。
- 印刷CSSが読み込めない、適用状態を確認できない、対象ブラウザで検証していない場合は印刷用表示を生成しない。
- 必須帰属、対象時点、参考情報、安全注意は維持する。

### 10.6 CSV / GeoJSON等のエクスポート

- 一般利用者向けエクスポートへ`EXACT_PRIVATE`・`SENSITIVE_DERIVED`を含めない。
- 列名を隠すだけでなく、値、メタデータ、ID、精度、時刻から復元できないことを確認する。
- GeoJSON等の精密経路エクスポートはMVPの公開共有とは分離し、必要性・本人確認・用途・再共有リスクを別Issueで審査する。
- 安全な用途・変換・権限を説明できないエクスポートはNo-Goとする。

### 10.7 管理・問い合わせ・削除対応画面

- 正確位置は業務上必要な最小範囲・最短時間だけ表示する。
- 権限、目的、閲覧理由、操作記録を必要とする。
- 通常の管理一覧・通知・ログへ精密位置を表示しない。
- 画面キャプチャ保護が利用不可の場合は、精密位置を表示せず参照IDと粗い範囲だけを候補とする。

## 11. 外部キャプチャ能力モデル

キャプチャ関連能力は次の独立軸で管理する。

### 11.1 キャプチャ抑止状態

- `CAPTURE_PREVENTION_ACTIVE`
- `CAPTURE_PREVENTION_INACTIVE`
- `CAPTURE_PREVENTION_UNAVAILABLE`
- `CAPTURE_PREVENTION_FAILED`
- `CAPTURE_PREVENTION_UNKNOWN`

### 11.2 キャプチャ検知状態

- `CAPTURE_DETECTION_ACTIVE`
- `CAPTURE_DETECTION_INACTIVE`
- `CAPTURE_DETECTION_UNAVAILABLE`
- `CAPTURE_DETECTION_FAILED`
- `CAPTURE_DETECTION_UNKNOWN`

### 11.3 アプリスイッチャー保護状態

- `APP_SWITCHER_PROTECTED`
- `APP_SWITCHER_UNPROTECTED`
- `APP_SWITCHER_PROTECTION_FAILED`
- `APP_SWITCHER_PROTECTION_UNKNOWN`

検知状態が`ACTIVE`でも、抑止状態を`ACTIVE`へ昇格させない。

抑止・検知・アプリスイッチャー保護のいずれかを必須条件とする画面では、状態が`FAILED`、`UNKNOWN`、`UNAVAILABLE`の場合、プライバシーセーフ表示へ切り替えるか情報本体を非表示にする。

## 12. プラットフォーム別境界

### 12.1 Web

- OSスクリーンショット、画面収録、ブラウザ拡張、開発者ツール、外部カメラ撮影の確実な抑止を前提にしない。
- 正確位置・生活拠点候補を通常表示する安全根拠として、JavaScriptによる右クリック禁止、キー操作禁止、透かし、注意文を使用しない。
- Webで公開・共有可能な画面は、外部キャプチャされても最低保護基準を満たすプライバシーセーフ表示とする。
- 印刷・PDFは第10.5節を満たす。

### 12.2 iOS候補

後続設計で最低限次を検証する。

- スクリーンショット
- 画面収録開始前・開始中・終了後
- AirPlay・ミラーリング・外部ディスプレイ候補
- アプリスイッチャー
- バックグラウンド遷移
- Control Center、Siri、通話等の中断
- 複数scene・画面遷移
- 保護API呼出失敗・アプリ再起動

キャプチャ検知後に画面を隠すだけでは、検知前の流出を防いだと扱わない。

### 12.3 Android候補

後続設計で最低限次を検証する。

- OSスクリーンショット
- 標準・主要画面録画
- メディアプロジェクション・画面共有候補
- 最近使ったアプリ画面
- バックグラウンド遷移
- マルチウィンドウ・ピクチャーインピクチャー候補
- 外部・非セキュアディスプレイ
- 端末メーカー差
- 保護フラグ適用失敗・画面遷移・アプリ再起動

`FLAG_SECURE`等の候補を採用しても、対象端末・OSの検証結果がない状態を`CAPTURE_PREVENTION_ACTIVE`と扱わない。

## 13. フォールバック

### 13.1 フォールバック優先順位

1. 精密位置・機微地点・原走行履歴を非表示にする。
2. 承認済み`PRIVACY_REDUCED`表示へ切り替える。
3. 地図を非表示にし、位置を含まない概要だけを表示する。
4. 画面・共有・印刷・エクスポート自体をブロックする。

### 13.2 フォールバック禁止事項

- 保護失敗時に直前の精密表示を残さない。
- キャッシュされた精密画像・地図タイル・サムネイルを表示しない。
- `保護できませんでした`という警告だけで精密表示を継続しない。
- 再試行中に機微情報を表示しない。
- 失敗を一般ログへ精密座標付きで記録しない。

## 14. 共有前プレビュー

共有・公開・印刷・一般エクスポートでは、確定前に次を表示する。

- 出力種別と公開範囲
- 変換後の地図・経路・地点
- 非表示・粗粒度化された対象の説明
- 表示される地名・ランドマーク・時刻粒度
- 帰属・対象時点・参考情報表示
- プライバシー変換版
- 再推定リスクがゼロではない旨
- 公開後の削除・公開範囲変更導線

利用者確認後にデータ・変換版・描画条件が変わった場合、再プレビューを必須とする。

プレビュー未確認、プレビュー生成失敗、実出力との差異検知時は`OUTPUT_BLOCKED`とする。

## 15. 状態モデル

### 15.1 プライバシー判定

- `PRIVACY_REVIEW_REQUIRED`: 判定・変換・再推定評価が未完了
- `PRIVACY_SAFE`: 承認済み条件を満たす
- `PRIVACY_BLOCKED`: 公開・共有・出力不可

### 15.2 出力状態

- `OUTPUT_PREVIEW_REQUIRED`
- `OUTPUT_PREVIEW_READY`
- `OUTPUT_APPROVED`
- `OUTPUT_BLOCKED`
- `OUTPUT_REVOKED`

### 15.3 導出ルール

- `PRIVACY_REVIEW_REQUIRED`では公開・共有・印刷・エクスポート不可。
- キャプチャ保護を必須とする画面で保護状態が`FAILED`、`UNKNOWN`、`UNAVAILABLE`なら`PRIVACY_SAFE`へ昇格しない。
- プレビューと実出力の版・ハッシュ・描画条件が不一致なら`OUTPUT_BLOCKED`。
- 公開範囲変更、削除、権利失効、変換版失効時は既存出力を`OUTPUT_REVOKED`とし、キャッシュ・OGP・共有表示を停止対象とする。

## 16. ログ・監査メタデータ

### 16.1 保存候補

- 対象走行記録の不透明な内部ID
- 公開範囲
- プライバシー分類
- 変換ポリシーID・版
- 判定日時
- プレビュー版・出力版の一致結果
- キャプチャ能力状態
- 対象OS・アプリ・ブラウザの版
- 共有・印刷・エクスポート結果
- 承認者・確認者
- 失敗理由区分・参照ID
- 出力取消・削除状態

### 16.2 保存禁止

- 正確な緯度・経度
- 原走行軌跡
- 生活拠点候補の座標・名称
- 公開前の非変換画像
- 位置付きEXIF
- 復元可能な位置断片
- 不要な個人・車両識別情報
- スクリーンショット・共有画像本体の無期限保存

公開Repository・一般ログには非機密な要約と参照IDだけを記録する。

## 17. 権限・職務分離

最低限次の責務を分離する。

- プライバシー要件責任者
- 変換アルゴリズム設計者
- 再推定リスク評価者
- セキュリティ確認者
- 法務・プライバシー確認者
- プラットフォーム別実装者
- テスト結果確認者
- リリース承認者

高リスクな閾値変更では、設計者と評価・承認者を同一操作で完結させない。

## 18. テストマトリクス

### 18.1 データ・再推定

| 観点 | 必須確認 |
| --- | --- |
| 単一記録 | 開始・終了・道路形状から生活拠点を推定できないか |
| 複数記録 | 共通端点・交差範囲・時間帯から推定できないか |
| 短距離 | 変換後に経路がほぼ消える場合の公開停止 |
| 都市部 | 建物・道路密度を考慮した再推定 |
| 郊外・過疎 | 一本道・単独施設・住宅の特定リスク |
| メタデータ | EXIF、地名、説明、時刻、IDから復元できないか |
| 表示条件 | 中心、ズーム、ラベル、サムネイルから推定できないか |

### 18.2 Web

- 対象ブラウザの通常表示
- 印刷プレビュー
- 紙印刷候補
- PDF保存
- `@media print`無効・読込失敗
- JavaScript無効・イベント未発火
- OGP・サムネイル・検索インデックス
- レスポンシブ表示・高解像度表示

### 18.3 iOS

- 対象OSの実機スクリーンショット
- 画面収録
- ミラーリング・外部表示候補
- アプリスイッチャー
- バックグラウンド・中断
- 保護API利用不可・失敗
- アプリ再起動・画面遷移

### 18.4 Android

- 対象OS・主要端末のスクリーンショット
- 画面録画・画面共有候補
- 最近使ったアプリ
- マルチウィンドウ
- 外部表示候補
- 保護フラグ失敗
- メーカー差・アプリ再起動・画面遷移

### 18.5 共有・出力

- プレビューと画像出力の一致
- プレビューとURL共有の一致
- 印刷・PDFとの一致
- 公開範囲変更後の再プレビュー
- 削除・取消後の共有URL、OGP、キャッシュ停止
- 帰属・対象時点・安全注意の維持

テストには実利用者の位置・走行履歴を使用せず、承認済みの合成・匿名テストデータを使用する。

## 19. Go / No-Goゲート

次をすべて満たす場合だけ、該当表示・出力をGo候補とする。

1. 位置分類を完了している。
2. 機微地点・機微パターンを評価している。
3. 承認済みプライバシー変換を適用している。
4. 単一・複数記録の再推定テストを通過している。
5. プレビューと実出力が一致している。
6. 公開範囲と最低保護基準を強制できる。
7. 必須帰属・対象時点・安全注意を維持している。
8. 該当プラットフォーム・OS・ブラウザで検証済みである。
9. キャプチャ保護必須画面では、抑止・検知・アプリスイッチャー保護状態を判定できる。
10. 保護失敗・不明時のフォールバックを検証している。
11. 印刷・PDF・OGP・共有キャッシュから機微情報を除外している。
12. 原座標・原走行履歴を一般ログ・公開Repositoryへ保存していない。
13. 削除・取消・公開範囲変更を共有表示へ伝播できる。
14. 人間・法務・安全・セキュリティ・プライバシー・アクセシビリティレビューを完了している。

1つでも判断不能・未確認の場合はNo-Goとする。

## 20. 受け入れ条件

- 機微地点と機微パターンの分類がある
- 精密位置、推定生活拠点、変換後情報を別分類として扱う
- 通常表示、公開、共有、印刷、エクスポート、管理画面の境界が定義されている
- 道路形状・反復記録・時刻・地名・画像等を組み合わせた再推定を考慮している
- ぼかし具体値の決定基準・承認主体が定義されている
- 具体的な距離・時間・訪問回数を未確定のままGoとしていない
- Webでスクリーンショット・画面収録を確実に防止できる前提を置いていない
- キャプチャ抑止・検知・アプリスイッチャー保護を分離している
- iOS / Androidの能力を対象OS・実機で検証する要件がある
- 保護失敗・不明・利用不可時にプライバシーセーフ表示へフォールバックする
- ブラウザ印刷・PDFで機微情報を除外する
- 共有前プレビューと実出力の一致を確認する
- URL、OGP、サムネイル、クライアントデータへ原座標を含めない
- 一般エクスポートへ精密位置・原走行軌跡を含めない
- 機微情報を一般ログ・公開Repositoryへ保存しない
- 削除・取消・公開範囲変更を既存出力へ伝播する
- 合成・匿名テストデータによるWeb / iOS / Android / 印刷 / 共有テストがある
- 走行中操作制限、帰属、保持・削除要件を弱めていない
- 実装・実データ・provider採用へ進んでいない
- AI生成物を人間がレビューする前提が明記されている

## 21. 未確定事項

- ぼかし距離・時間・訪問回数・滞在時間の具体値

- 再推定リスクの評価指標・合格基準
- 本人向け精密表示を許可する画面・時間・認証条件
- Webでの精密位置表示範囲
- Expo / React Native / ネイティブ実装の採否
- 対象iOS / Androidバージョン・端末
- キャプチャ保護API・アプリスイッチャー保護方式
- 印刷・PDFの対象ブラウザ
- URL共有・OGP・キャッシュ失効方式
