# 愛車の整備・給油・走行距離履歴 要件定義（Issue #138）

## 1. 目的

RouteGarageのガレージ機能を、車両プロフィールを保存するだけの領域から、愛車を継続的に管理できる個人用記録領域へ拡張する。

本機能では、ユーザーが自分の車両について次を時系列で記録・確認できることを目的とする。

- 整備履歴
- 給油履歴
- 走行距離履歴
- 入力済み費用の集計
- 十分なデータがある場合の燃費表示
- ユーザー自身が設定した次回メンテナンス目安

本機能は、整備の安全性、故障状態、道路運送車両法等への適合性、車検合否、走行可否を判定または保証するものではない。

## 2. 背景

既存MVP要件ではガレージについて以下のみが定義されている。

- `FR-GARAGE-01`: 車両名、年式、メモの管理
- `FR-GARAGE-02`: カスタム情報の自由記述
- `FR-GARAGE-03`: 違法改造を助長する表現の禁止

一方で、車両を継続利用するユーザー価値として重要な「いつ、何を整備したか」「どの程度給油したか」「その時点の走行距離はいくつか」が未定義である。

Issue #138では、DB/API/UIを実装せず、後続設計へ渡せる機能要件・認可・データ整合性・安全境界を定義する。

## 3. 対象ユーザー

- 自分のクルマまたはバイクの整備履歴を記録したい個人ユーザー
- 給油量・費用・燃費を振り返りたい個人ユーザー
- オイル交換等の次回目安を自分で管理したい個人ユーザー

法人の整備事業者、ショップ、フリート管理はMVP対象外とする。

## 4. 前提・仮定

### 4.1 確定前提

- 記録はRouteGarage上でユーザーが所有する車両プロフィールに紐づく。
- 履歴は本人限定を既定とする。
- 入力・編集は停車中または走行後に行う。
- GPS、OBD、VIN等を使った自動入力をMVPでは行わない。
- 実店舗住所や現在地を必須入力にしない。

### 4.2 仮定

- 走行距離は原則として車両のオドメーター表示値をユーザーが手入力する。
- 通貨はMVP公開対象が日本国内であるためJPYを初期表示単位候補とするが、データ型・多通貨対応は後続設計で確定する。
- 燃費表示は満タン法を初期候補とする。

### 4.3 要確認

- 車両プロフィールを「削除」する場合の履歴保持期間
- 車両アーカイブ機能を既存ガレージへ追加するか
- 次回目安をWeb内通知へ接続するか
- 期間費用集計をMVPへ含めるか内部βへ分離するか
- 燃費推移グラフを初期MVPへ含めるか

## 5. 用語

| 用語 | 定義 |
| --- | --- |
| 車両 | ユーザーがRouteGarageへ登録した本人所有/管理対象の車両プロフィール |
| 整備記録 | 点検、交換、修理、洗車、カスタム等をユーザーが記録する個人履歴 |
| 給油記録 | 給油日、走行距離、給油量、満タン可否等を持つ個人履歴 |
| 走行距離値 | 各履歴に紐づけられるオドメーター表示値 |
| 訂正 | 誤入力を履歴として追跡可能な形で修正する操作 |
| メーター交換 | オドメーター値が単調増加しなくなる正当な理由の一つ |
| 次回目安 | ユーザー自身が設定する日付/距離の管理目標。安全診断ではない |
| 区間燃費 | 満タン法の成立条件を満たす場合だけ表示する走行距離÷対象給油量 |

## 6. 機能範囲

### 6.1 整備履歴

ユーザーは所有車両に整備記録を追加できる。

#### 必須項目

- 対象車両
- 実施日
- 整備カテゴリ
- 作業内容

#### 任意項目

- 走行距離
- 店舗名/作業者メモ
- 費用
- 個人メモ
- 次回目安日
- 次回目安走行距離

#### 初期カテゴリ

- `OIL`
- `FILTER`
- `TIRE`
- `BRAKE`
- `BATTERY`
- `INSPECTION`
- `REPAIR`
- `WASH_DETAILING`
- `CUSTOM`
- `OTHER`

表示名は日本語化してよいが、詳細設計時は永続値と表示文言を分離する。

### 6.2 給油履歴

ユーザーは所有車両に給油記録を追加できる。

#### 必須項目

- 対象車両
- 給油日
- 走行距離
- 給油量
- 満タンフラグ

#### 任意項目

- 合計金額
- 単価
- 個人メモ

給油量は0より大きい値のみ通常記録として扱う。

### 6.3 走行距離履歴

整備記録、給油記録等で入力された走行距離を、車両単位で整合性確認できること。

- 通常記録では直前の有効走行距離以上を原則とする。
- 同じ走行距離値は許容する。例: 同日に複数の整備を登録する場合。
- 直前値より小さい値は通常の追加として黙って確定しない。
- 距離逆転時は「入力訂正」「メーター交換」「その他の例外」等の明示理由を要求する候補とする。
- 訂正前後を監査可能にするため、単純な破壊的上書きだけに依存しない設計へ引き継ぐ。

詳細な不変条件は `garage-maintenance-fuel-odometer-invariants.md` を正本候補とする。

### 6.4 燃費表示

燃費は、必要な記録が揃っている場合だけ表示する。

- 初期方式は満タン法候補とする。
- 前回の有効な満タン記録を開始点とする。
- 今回の有効な満タン記録を終了点とする。
- 途中に部分給油がある場合、その期間の給油量を合算する。
- `区間走行距離 / 対象期間給油量`で算出する候補とする。
- 前回満タンが存在しない場合は算出しない。
- 距離が逆転または整合性不明の場合は算出しない。
- 対象給油量が0以下の場合は算出しない。
- メーター交換をまたぐ区間は、補正ルール確定前は算出しない。
- 算出不能を`0 km/L`として表示しない。

### 6.5 次回メンテナンス目安

ユーザーは整備記録から次回目安を任意設定できる。

- 日付ベース
- 走行距離ベース
- 両方

システムはユーザー入力値との比較結果のみを表示する。

表示候補:

- 目安まで余裕あり
- 目安が近い
- 設定日を超過
- 設定走行距離を超過
- 判定不能

「安全」「危険」「交換必須」「走行不可」等の診断表現は、メーカー一次情報や専門家レビューを伴う別機能として承認されない限り使用しない。

### 6.6 一覧・検索・集計

車両単位で履歴を時系列表示できること。

絞り込み候補:

- 記録種別
- 整備カテゴリ
- 期間
- 費用入力有無

並び順:

- 新しい順
- 古い順

集計候補:

- 期間内の入力済み整備費用合計
- 期間内の入力済み給油費用合計
- 期間内の入力済み総費用
- 有効な区間燃費の推移

欠損値を0円・0L・0kmとして勝手に補完しない。

## 7. 機能要件

### 7.1 整備

- `FR-GARAGE-HIST-01`: 所有車両へ整備記録を追加できること。
- `FR-GARAGE-HIST-02`: 整備記録を本人が閲覧・編集・削除できること。
- `FR-GARAGE-HIST-03`: 整備カテゴリ、実施日、作業内容を必須として扱えること。
- `FR-GARAGE-HIST-04`: 走行距離、店舗名、費用、メモ、次回目安を任意入力できること。
- `FR-GARAGE-HIST-05`: 違法改造を助長する表示・導線を追加しないこと。

### 7.2 給油

- `FR-GARAGE-FUEL-01`: 所有車両へ給油記録を追加できること。
- `FR-GARAGE-FUEL-02`: 給油日、走行距離、給油量、満タンフラグを必須として扱えること。
- `FR-GARAGE-FUEL-03`: 合計金額、単価、メモを任意入力できること。
- `FR-GARAGE-FUEL-04`: 給油量0以下を有効な給油記録として扱わないこと。
- `FR-GARAGE-FUEL-05`: 本人が給油記録を編集・削除できること。

### 7.3 走行距離

- `FR-GARAGE-ODO-01`: 車両単位で入力済み走行距離の時系列整合性を確認できること。
- `FR-GARAGE-ODO-02`: 直前値と同値の走行距離を許容できること。
- `FR-GARAGE-ODO-03`: 直前値より小さい走行距離を通常記録として無条件確定しないこと。
- `FR-GARAGE-ODO-04`: 訂正・メーター交換等を通常記録と区別できること。
- `FR-GARAGE-ODO-05`: 距離整合性が失われた区間で燃費や距離ベース目安を断定表示しないこと。

### 7.4 燃費

- `FR-GARAGE-ECO-01`: 満タン法の成立条件を満たす区間だけ燃費を算出できること。
- `FR-GARAGE-ECO-02`: 部分給油を挟む場合は対象区間の給油量を合算できること。
- `FR-GARAGE-ECO-03`: 算出不能と0km/Lを区別できること。
- `FR-GARAGE-ECO-04`: 履歴の訂正・削除後に影響を受ける燃費結果を再評価できる設計へ引き継ぐこと。

### 7.5 次回目安

- `FR-GARAGE-REM-01`: 次回目安日を任意設定できること。
- `FR-GARAGE-REM-02`: 次回目安走行距離を任意設定できること。
- `FR-GARAGE-REM-03`: 設定値と現在の有効値を比較して状態表示できること。
- `FR-GARAGE-REM-04`: システムがメーカー推奨値や安全判定を自動生成しないこと。

### 7.6 一覧・集計

- `FR-GARAGE-LIST-01`: 所有車両の整備・給油履歴を時系列一覧できること。
- `FR-GARAGE-LIST-02`: 種別・カテゴリ・期間で絞り込めること。
- `FR-GARAGE-LIST-03`: 入力値だけを対象とした費用集計ができる候補を持つこと。
- `FR-GARAGE-LIST-04`: 不足値を0として補完した集計を表示しないこと。

## 8. 認証・認可

### 8.1 所有者限定

- 作成、編集、削除、一覧、詳細、集計は対象車両の所有者本人だけが行えること。
- 車両ID・履歴IDを推測しても他ユーザーの履歴内容を取得できないこと。
- 公開車両プロフィールから整備費用、給油履歴、走行距離履歴へ遷移できないこと。
- 管理運用で参照権限が必要な場合は別の管理者権限要件を定義すること。

### 8.2 将来の公開

整備履歴や燃費の公開はMVP対象外とする。

将来導入する場合は、以下を別Issueで定義する。

- 項目単位の公開範囲
- 公開前確認
- 店舗名や時系列から生活圏を推定されるリスク
- 走行距離から車両利用状況を推測されるリスク
- 削除/非公開化の反映

## 9. 安全性

- 記録追加・編集・削除は停車中または走行後に限定する。
- 走行中に入力を促す通知・連続操作導線を提供しない。
- 次回目安は「ユーザーが設定した管理目安」であることを明示する。
- 整備記録だけから故障診断や走行可否判定をしない。
- 車検・法令適合を保証しない。
- カスタム履歴で危険運転や違法改造を推奨しない。

## 10. プライバシー

- GPS・現在地・店舗座標を自動取得しない。
- 店舗名は自由入力の任意項目とする。
- 店舗住所はMVP必須項目にしない。
- VIN、ナンバープレート、車検証画像、整備明細画像を要求しない。
- 履歴は本人限定を初期値とする。
- ログ・分析へメモ本文等を無条件送信しない設計へ引き継ぐ。

## 11. データ整合性

### 11.1 数値

- 給油量は0より大きいこと。
- 費用は0以上または未入力であること。
- 単価は0以上または未入力であること。
- 走行距離は0以上であること。
- NaN、Infinity、桁あふれ等を入力値として確定しない。

### 11.2 訂正・削除

- 履歴の変更で燃費・費用集計・次回目安が変わる場合、古い派生値を確定値として残さない。
- 同時編集時に古い画面からの保存で最新変更を無条件上書きしない設計へ引き継ぐ。
- 訂正理由・変更履歴の保持範囲は詳細設計で確定する。

## 12. 車両状態との整合性

### 12.1 アーカイブ候補

推奨案として、売却・乗換等で日常利用しなくなった車両を即削除せずアーカイブできる状態を検討する。

アーカイブ時:

- 過去履歴は本人が閲覧できる候補とする。
- 新規記録追加は初期値として停止する候補とする。
- 公開車両プロフィールが存在する場合は別の公開状態ルールに従う。

### 12.2 完全削除

完全削除を提供する場合:

- 履歴が存在することを明示する。
- 削除対象範囲を確認する。
- 誤操作防止の明示確認を要求する。
- バックアップ/ログ/派生集計を含む削除SLAは後続運用設計で定義する。

## 13. 画面責務

Issue #138では既存 `screen-list.md` を直接大規模更新せず、レビュー用deltaとして次を定義する。

- SCR-16拡張: ガレージ管理からメンテナンス履歴への導線
- SCR-31候補: 愛車メンテナンス履歴一覧
- SCR-32候補: 整備記録作成/編集
- SCR-33候補: 給油記録作成/編集
- SCR-34候補: メンテナンス履歴詳細/集計

画面IDは既存delta統合時に重複を再確認し、競合があれば採番し直す。

## 14. 対象外

- OBD/ECU/ドラレコ等の外部デバイス連携
- GPSによる自動走行距離取得
- VINからの車種・部品情報自動取得
- メーカー整備データAPI
- 店舗予約
- 整備料金決済
- レシートOCR
- 整備画像/レシート画像保存
- AI故障診断
- AI整備安全診断
- 走行可能/走行不可の自動判定
- 車検適合保証
- 他ユーザーへの履歴公開
- 整備事業者向け業務管理

## 15. 受け入れ条件

- 整備・給油・走行距離の責務が区別されている。
- 各入力項目の必須/任意が明確である。
- 距離逆転、訂正、メーター交換の扱いが定義されている。
- 燃費を算出できる条件/できない条件が明確である。
- 次回目安と安全診断が分離されている。
- 本人限定の認可要件がある。
- 車両アーカイブ/削除時の履歴影響がレビュー対象になっている。
- 既存FR-GARAGE-01〜03を弱めていない。
- 実DB/API/UI/providerを本Issueで採用していない。

## 16. テスト観点

### 正常系

- 整備記録を必要項目付きで登録できる。
- 給油記録を必要項目付きで登録できる。
- 連続する有効な満タン区間で燃費算出条件を満たせる。
- 部分給油を挟む区間を扱える。
- 日付/距離ベースの次回目安を設定できる。
- 車両別・期間別に履歴を確認できる。

### 異常系

- 給油量0/負数
- 費用負数
- 単価負数
- 走行距離負数
- 走行距離逆転
- 所有していない車両への記録追加
- 他ユーザー履歴のID直指定
- 不正日付
- 訂正後に古い燃費値が残る

### 境界値

- 走行距離0
- 直前と同じ走行距離
- 満タン記録1件のみ
- 部分給油1件/複数件
- 0円の整備
- 費用未入力
- 非常に大きな走行距離/費用/給油量
- メーター交換直前/直後
- 車両アーカイブ中の追加操作

### 認可

- 所有者
- 非所有者
- 未ログイン
- 管理者権限候補（後続設計）

### データ不整合

- 履歴編集による時系列逆転
- 履歴削除で満タン区間が成立しなくなる
- 給油量訂正で燃費が変わる
- 走行距離訂正で次回目安状態が変わる

### 回帰

- 既存ガレージプロフィール管理
- 公開車両のストーリー参照
- 違法改造助長防止
- 走行中操作禁止
- 位置情報最小化

## 17. 後続設計へ渡す事項

- 永続モデルと履歴/監査モデル
- 精度・decimal桁数
- optimistic concurrency / versioning
- 燃費再計算範囲
- 車両アーカイブ/完全削除状態
- 通知方式
- 集計キャッシュ有無
- データ保持・バックアップ削除SLA
- API認可境界

## 18. Do Not Proceed

Issue #138の要件レビュー完了だけを、以下の開始承認として扱わない。

- DB schema作成
- API endpoint作成
- Auth/認可実装
- UI実装
- GPS/OBD/VIN連携
- 外部API/provider採用
- 実ユーザーデータ投入
- AI整備診断
