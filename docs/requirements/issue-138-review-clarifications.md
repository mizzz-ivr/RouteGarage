# Issue #138 レビュー補足・不変条件追加

## 1. 目的

PR #140のCodexレビューで確認された要件の曖昧さを解消し、後続設計・実装が任意の解釈を補完しないための追加要件を定義する。

本書はIssue #138のレビュー中に追加された**規範的な補足**とする。Issue #138配下の他文書と内容が競合する場合、PR #140の人間レビューで統合判断するまで本書のより厳しい制約を優先する。

正本統合時には、本書だけを恒久的な例外資料として残すのではなく、`garage-maintenance-history-requirements.md`および`garage-maintenance-fuel-odometer-invariants.md`へ内容を統合して重複を解消する。

## 2. 公開車両プロフィール経由の非漏えい

### 2.1 追加要件

Owner-only認可は履歴IDの直指定拒否だけでは不十分である。

公開車両プロフィール、公開ストーリー内の車両参照、その他公開API/画面から、メンテナンス履歴由来の非公開情報を取得できないこと。

少なくとも次を公開レスポンス/画面へ含めない。

- 整備履歴本文
- 整備費用
- 給油履歴
- 給油量
- 給油金額・単価
- 個々の走行距離履歴
- 最新走行距離候補
- 区間燃費・燃費集計
- 次回メンテナンス目安日
- 次回メンテナンス目安走行距離
- 整備/給油の個人メモ
- 店舗名/作業者メモ

公開車両プロフィールが正常に閲覧できることと、非公開メンテナンス情報が取得できないことを同時に検証する。

### 2.2 必須テスト

#### 公開プロフィール正常閲覧

前提:

- ユーザーAが公開車両プロフィールを持つ。
- その車両には整備・給油・走行距離・次回目安の非公開履歴が存在する。
- ユーザーBまたは未ログイン利用者が公開プロフィールを閲覧する。

期待:

- 公開を許可された車両プロフィール項目は正常に表示できる。
- 上記の非公開メンテナンス項目はレスポンス、HTML、serialized props、client state等へ含まれない。
- 「画面で隠すだけ」で非公開値をクライアントへ送信しない。

#### 公開ストーリー内の車両参照

前提:

- 公開ストーリーがユーザーAの公開車両プロフィールを参照する。

期待:

- ストーリー表示に必要な公開車両情報だけ取得する。
- 整備・給油・走行距離・燃費・次回目安等を参照レスポンスへ含めない。

#### ID直指定との独立確認

- 履歴ID直指定が拒否されること。
- 公開プロフィール取得が成功する経路でも非公開値が漏れないこと。

この2つを別テストとして扱う。

## 3. 同日給油記録の完全な論理順序

### 3.1 問題

MVPでは給油日の粒度を日単位としているため、同一車両・同一日に複数の給油記録がある場合、日付だけでは「前回満タンの後」「今回満タンまで」を一意に決められない。

特に同じ走行距離値を許容しているため、部分給油と満タン給油の順序が曖昧なまま燃費計算すると結果が非決定的になる。

### 3.2 追加不変条件 `FUEL-ORDER-INV-01`

燃費計算へ使用する給油記録には、車両単位で完全な論理順序を決定できること。

論理順序は少なくとも次で比較できる必要がある。

1. 給油日
2. 同一給油日内の順序

同一日内順序の具体的な永続フィールド名・型は詳細設計で決めるため、本要件では`same_day_order`という論理概念として扱う。

### 3.3 `FUEL-ORDER-INV-02`: 作成日時を業務順序にしない

`created_at`、DB ID、UUID、API到着順等を、ユーザーが実際に給油した順番の代替として自動採用しない。

後から過去日の記録を追加できるため、作成順と出来事順は一致しない。

### 3.4 `FUEL-ORDER-INV-03`: 順序不明は算出不能

同一車両・同一日に複数給油が存在し、区間境界に影響するにもかかわらず同日内順序を確定できない場合、その給油記録を含む燃費区間は算出不能とする。

推測で部分給油を現在区間/次区間へ振り分けない。

### 3.5 `FUEL-ORDER-INV-04`: 順序訂正で再評価

同日内順序を訂正した場合、影響する直前・直後の満タン区間を再構成し、派生燃費を再評価する。

### 3.6 必須テスト

- 同一日に「部分給油 → 満タン」がある。
- 同一日に「満タン → 部分給油」がある。
- 同一日・同一走行距離で部分給油と満タンがある。
- 同一日内順序が未確定である。
- 同一日内順序を訂正する。
- 作成日時と実際の論理順序が逆である。

期待:

- 順序確定済みの場合のみ、その論理順序に従って区間を構成する。
- 順序不明の場合は燃費を算出しない。
- 作成日時/IDで暗黙補完しない。

## 4. 日付・順序訂正時の派生値再評価

### 4.1 `DERIVED-INV-06`: 給油日訂正

給油日を変更すると、部分給油が属する満タン区間または満タン境界自体が変わる可能性がある。

給油日訂正時は少なくとも次を再評価する。

- 訂正前に属していた満タン区間
- 訂正後に属する満タン区間
- 直前の有効満タン境界
- 直後の有効満タン境界
- 区間燃費の算出可否

### 4.2 `DERIVED-INV-07`: 同日内順序訂正

同日内順序の訂正時は、影響する前後の満タン区間を再構成する。

### 4.3 `DERIVED-INV-08`: 整備記録の日付/走行距離訂正

走行距離付き整備記録の日付または走行距離を訂正した場合、少なくとも次を再評価する。

- 車両の走行距離時系列整合性
- 最新有効走行距離候補
- 距離ベース次回目安
- 距離整合性を前提として有効扱いしていた燃費区間

### 4.4 `DERIVED-INV-09`: 走行距離付き整備記録削除

走行距離付き整備記録を削除した場合、その記録が存在していたことで発生/解消していた走行距離逆転が変化する可能性がある。

削除後は少なくとも次を再評価する。

- 前後の走行距離整合性
- 最新有効走行距離候補
- 距離ベース次回目安
- 整合性判定に依存する燃費区間

整備記録に次回目安自体が紐づいている場合は、その目安表示も再評価する。

### 4.5 必須テスト

- 部分給油の日付を満タン境界の前から後へ変更する。
- 満タン給油の日付を変更して区間境界が変わる。
- 同一日内順序を入れ替える。
- 走行距離付き整備記録の日付を変更する。
- 走行距離付き整備記録の走行距離を変更する。
- 走行距離付き整備記録を削除し、距離逆転が解消する。
- 走行距離付き整備記録を削除し、最新有効走行距離候補が変わる。

古い派生値をキャッシュ等に残して確定値として表示しない。

## 5. 「目安が近い」の扱い

### 5.1 問題

「目安が近い」を表示するには、設定日まで何日前、設定走行距離まで何km以内を近いとみなすかという別の閾値が必要になる。

Issue #138では、その閾値・設定主体・日付と距離の優先順位を定義していない。

### 5.2 決定 `REM-INV-04`

**「目安が近い」はIssue #138のMVP表示対象から外す。**

MVPで判定可能な状態候補は次に限定する。

- 設定値未超過
- 設定日超過
- 設定走行距離超過
- 日付・距離の両方超過
- 判定不能

日付/距離のどちらかしか設定されていない場合は、設定済み側だけを評価する。

### 5.3 将来採用条件

「目安が近い」を将来追加する場合は、別要件として少なくとも次を確定する。

- 日付の近接閾値
- 距離の近接閾値
- 閾値を固定値にするかユーザー設定にするか
- 日付/距離の両方が設定された場合の表示優先順位
- 通知へ接続する場合の頻度・抑制ルール

これらを未確定のまま後続実装が任意値を採用してはならない。

## 6. 追加回帰テスト

### 公開境界

- 公開車両プロフィールの正常レスポンスへ非公開メンテナンス値を含めない。
- 公開ストーリーの車両参照へ非公開メンテナンス値を含めない。
- 非所有者/未ログインが履歴IDを直指定しても取得できない。

### 時系列

- 過去日付への後追い登録。
- 同日複数給油。
- 同日同走行距離。
- 同日順序未確定。
- 同日順序訂正。
- 給油日訂正。
- 整備実施日訂正。

### 派生値

- 給油量訂正。
- 給油日訂正。
- 満タンフラグ変更。
- 同日内順序訂正。
- 給油記録削除。
- 走行距離付き整備記録の日付/距離訂正。
- 走行距離付き整備記録削除。

## 7. 後続設計へ渡す事項

本書では次を実装方式として確定しない。

- `same_day_order`の実際のカラム名/型
- 同日順序入力UI
- 順序更新API
- optimistic concurrency方式
- 派生値を都度計算するかキャッシュするか
- 再計算job/transaction境界

ただし、**完全な論理順序を確定できない区間では燃費を算出しない**という要件は後続設計で弱めない。
