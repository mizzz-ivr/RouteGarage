# ドライブストーリー公開期限 不変条件

## 1. 位置づけ

本資料は `docs/requirements/drive-story-requirements.md` の公開期限要件を補足する規範文書である。

Issue #130 / PR #131のレビューで、非公開化・再公開・編集等によって24時間の公開期限が意図せず延長されることを防ぐため、期限に関する不変条件を定義する。

本資料は期限処理方式、DB、バッチ、ジョブ、CDN等の実装を決定しない。

## 2. 用語

- `published_at`: 対象ストーリーが初めて公開に成功したUTC時刻。初回公開後は変更しない。
- `expires_at`: `published_at + 24 hours`で一度だけ算出するUTC時刻。初回公開後は変更しない。
- 公開前レビュー: `PUBLIC_REVIEW_REQUIRED`で画像・短文・参照・安全・プライバシーを確認する処理。期限は開始しない。
- 非公開化: 公開期限内のストーリーを一般閲覧者から非表示にする操作。期限を停止・延長しない。
- 再公開: 非公開化した同一ストーリーを、元の`expires_at`より前に再度`PUBLIC`へ戻す操作候補。
- 再共有: 期限切れまたは削除済みの内容を、新しいストーリーIDとして新規作成・公開前確認すること。

## 3. 確定ルール

1. `published_at`と`expires_at`は初回公開成功時に同一トランザクション境界で設定する候補とする。
2. 公開前レビュー開始時、画像アップロード時、下書き保存時には期限を開始しない。
3. `published_at`と`expires_at`は初回公開後に更新しない。
4. 非公開化しても期限計算を一時停止しない。
5. 再公開を許可する場合も、元の`expires_at`までの残り時間だけ公開できる。
6. 再公開時に`published_at`または`expires_at`を再計算しない。
7. 公開後の短文修正を将来許可する場合、公開前確認を再要求しても期限は延長しない。
8. 参照リンクの変更・解除・再設定で期限を延長しない。
9. 管理者停止の解除可否を将来定義する場合も、同一ストーリーの期限は延長しない。
10. `now >= expires_at`のストーリーは`EXPIRED`として一般公開へ戻さない。
11. 期限切れ内容を再度共有する場合は、新しいストーリーID・新しい公開前確認・新しい`published_at`を持つ別コンテンツとして扱う。
12. 新規ストーリーへ複製する場合、元ストーリーの画像・短文・参照情報を無確認で公開せず、EXIF・映り込み・権利・参照先状態を再確認する。
13. サーバー再起動、バッチ停止、ジョブ再実行、タイムゾーン変更、夏時間、UI表示不具合で期限を延長しない。
14. 期限判定は公開一覧生成時だけでなく、ストーリー取得時・画像配信認可時にも行う。
15. CDNやキャッシュの失効遅延を理由に24時間超過公開を許容しない。具体方式とSLOは後続設計で定義する。

## 4. 状態遷移上の制約

### 4.1 初回公開

`DRAFT / PRIVATE`
→ `PUBLIC_REVIEW_REQUIRED`
→ 公開成功時に`PUBLISHED / PUBLIC`
→ `published_at`と`expires_at`を設定

公開処理が失敗した場合は、公開成功として時刻を確定しない。部分成功時のロールバック・再試行方法は後続設計で定義する。

### 4.2 非公開化・再公開

- `PUBLISHED / PUBLIC`から`PUBLISHED / PRIVATE`への非公開化候補を認める。
- `now < expires_at`かつ安全・権利・プライバシー・認可条件を満たす場合だけ、再レビュー後に元の期限まで再公開できる候補とする。
- `now >= expires_at`の場合は再公開不可とする。
- `STOPPED`は投稿者操作で解除できない。

### 4.3 期限切れ

`now >= expires_at`の場合:

1. 一般閲覧を拒否する。
2. `EXPIRED`として扱う。
3. ホーム、一覧、プロフィール、直接URL、参照導線から除外する。
4. 画像配信認可を拒否する。
5. 未解決通報・監査証跡は別ポリシーに従い維持する。
6. 物理削除完了とは表示しない。

### 4.4 削除・停止との競合

公開可否の優先順位:

1. `STOPPED`
2. `DELETED`
3. `EXPIRED`または`now >= expires_at`
4. `PRIVATE` / `PUBLIC_REVIEW_REQUIRED`
5. `PUBLIC`

いずれの状態でも`expires_at`は更新しない。

## 5. 冪等性・競合要件

- 同一ストーリーへの同時公開要求で複数の`published_at`を生成しない。
- 公開APIの再試行で期限を延長しない。
- 二重クリック・ネットワーク再送・ジョブ再実行で期限を延長しない。
- 非公開化と再公開が競合した場合、認可済みの最新状態を採用しても期限値は変更しない。
- 期限到達と再公開が競合した場合、期限到達を優先する。
- 期限到達と削除要求・管理者停止が競合した場合、公開停止を保証し、監査上の最終理由を追跡できるようにする。

## 6. テスト観点

### 正常系

- 初回公開成功時に一度だけ`published_at`と`expires_at`が設定される。
- 非公開化後に再公開しても`expires_at`が変わらない。
- 公開前レビューを複数回実行しても期限が開始・延長されない。
- 期限前の再公開は元の残り時間だけ閲覧できる。
- 期限切れ内容を新規ストーリーとして再共有できる候補が、元ストーリーと別IDになる。

### 異常系

- 公開API再試行で期限が24時間後へ再設定される。
- 短文編集や参照変更で期限が延長される。
- 非公開中は期限計算が停止する。
- `EXPIRED`を同一IDで`PUBLIC`へ戻す。
- 管理者停止解除で期限を再設定する。
- CDN URLが元の`expires_at`後も閲覧できる。

### 境界値

- 初回公開処理の同時実行。
- 23時間59分59秒で非公開化・再公開。
- 24時間ちょうどの再公開要求。
- 期限到達と公開API再試行の競合。
- UTC日付変更、日本時間日付変更。
- サーバー時刻ずれ、再起動、バッチ遅延。

### 回帰

- 24時間を「画面に表示した時刻から24時間」と解釈しない。
- アプリ再インストール、ログアウト、タイムゾーン変更で期限を変えない。
- 期限切れと物理削除・通報証跡保持を混同しない。
- `STOPPED`の優先順位を弱めない。
