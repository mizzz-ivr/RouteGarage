# ドライブストーリー投稿・閲覧機能 要件定義

## 1. 文書情報

- 対象Issue: #130
- 対象フェーズ: Phase 1 / Requirements Definition
- 対象プロダクト: RouteGarage Web MVP拡張候補
- 状態: 人間レビュー待ち
- 実装: 対象外

## 2. 目的

ドライブやツーリングの一場面を、長期保存を前提とする通常投稿とは分離し、画像と短文で24時間だけ共有できる`ドライブストーリー`の要件を定義する。

本機能は、気軽な共有を可能にしつつ、走行中操作、現在地推定、生活拠点推定、画像の位置情報、人物・車両情報の映り込み、期限切れコンテンツの通報対応等のリスクを抑えることを目的とする。

## 3. 基本方針

- RouteGarage内の機能名は`ドライブストーリー`とする。
- 走行中の撮影・作成・編集・投稿を前提にしない。
- 投稿、公開、非公開化、削除は停車中または走行後に行う。
- 正確な現在地を取得・自動付与・公開しない。
- 公開初期値は`PRIVATE`とする。
- 公開時は`PUBLIC_REVIEW_REQUIRED`を経由する。
- 公開期限は`published_at`から24時間とする。
- 期限到達時は公開表示を直ちに停止する。
- 期限切れと物理削除、監査証跡保持を同一視しない。
- `STOPPED`を他の公開状態・所有者操作より優先する。
- 通常投稿、走行記録、スポット、車両プロフィールの閲覧権限をストーリー経由で復活させない。
- AI判定だけで公開可否・違反確定を行わない。

## 4. 対象ユーザー

- ドライブやツーリング後に、その日の一場面を短く共有したいユーザー
- 絶景、道の駅、PA/SA、飲食、愛車等の短い体験を閲覧したいユーザー
- 通常投稿として恒久保存するほどではない内容を一時共有したいユーザー

## 5. 用語・責務

| 用語 | 責務 |
| --- | --- |
| ドライブストーリー | 24時間限定で公開する画像・短文コンテンツ |
| 通常投稿 | 継続公開・保存を前提とするコミュニティ投稿 |
| 走行記録 | 実際の走行日、距離、エリア、メモ等の実績 |
| スポット | 場所情報・説明・画像を持つ共有対象 |
| 参照リンク | 公開済みスポット、走行記録、車両プロフィールへの関連付け |
| 公開期限 | `published_at`から24時間後の`expires_at` |
| 公開停止 | 公開導線・閲覧API等から見えない状態にすること |
| 物理削除 | ストレージ・DB等から実データを削除すること。詳細設計で確定 |

ストーリーから通常投稿・走行記録へ自動変換しない。通常投稿・走行記録からストーリーを作成する場合も、公開内容を再確認した独立コンテンツとして扱う。

## 6. 機能スコープ

### 6.1 投稿作成

- 画像1件と短文を基本単位とする。
- 対応画像形式は既存MVPに合わせJPEG / PNGとする。
- 画像なしの文字だけ投稿を許可するかは未確定とする。
- 下書きを作成・編集・破棄できること。
- 公開前に画像・短文・参照リンク・公開範囲を確認できること。
- 公開前に停車中または走行後であることを確認する注意を表示すること。
- 公開後の画像差し替えは不可とし、必要な場合は削除して再投稿する候補とする。
- 公開後の短文修正可否は後続設計で確定する。

### 6.2 参照リンク

ストーリーは次の公開済みコンテンツを任意で1件参照できる候補とする。

- 公開スポット
- 投稿者本人の公開走行記録
- 投稿者本人の公開車両プロフィール

参照リンクは独立した参照であり、参照先の本文、画像、正確位置をストーリーへ恒久複製しない。

参照先が非公開・削除・権利停止・安全停止・プライバシー停止になった場合:

1. ストーリー上の参照リンクを直ちに無効化する。
2. 参照先由来の名称・サムネイル・位置情報を表示しない。
3. ストーリー自体の画像・短文が独立して公開可能か再判定する。
4. 独立して公開できない場合はストーリーを`STOPPED`とする。
5. 失った閲覧権限をストーリー経由で復活させない。

### 6.3 公開・非公開化・削除

- 公開初期値は`PRIVATE`とする。
- `PRIVATE`から直接`PUBLIC`へ遷移させず、`PUBLIC_REVIEW_REQUIRED`を経由する。
- 投稿者は期限前に非公開化できること。
- 投稿者は期限前に削除要求を行えること。
- 投稿者の削除要求より管理者の`STOPPED`・証跡保全を優先できること。
- 削除要求後は公開表示を先に停止すること。
- 物理削除完了まで削除済み表示や復元可否をどう扱うかは後続設計で確定する。

### 6.4 閲覧

- ホームまたはコミュニティ画面から公開中ストーリーへ遷移できること。
- 投稿者単位で公開中ストーリーをまとめて表示できること。
- 前・次のストーリーへ移動できること。
- 公開残り時間または公開時刻を表示できること。
- 自動再生・自動送りを採用する場合も走行中の連続閲覧を助長しないこと。
- 閲覧中に通報・個別非表示へ遷移できること。
- 期限切れ、削除、停止済みストーリーを通常閲覧者へ返さないこと。

### 6.5 非表示・ミュート

- 閲覧者は特定ストーリーを自分の一覧から非表示にできること。
- 投稿者単位のストーリーミュートは公開版の必須候補とする。
- ミュートは投稿者の通常投稿・スポット等へ自動適用しない。
- ブロック機能との関係はコミュニティ全体の後続Issueで確定する。

### 6.6 通報

- 公開ストーリーから2操作以内で通報フォームへ到達できること。
- 通報対象のストーリーID、投稿者ID、公開時刻、通報時点状態を追跡できること。
- 期限切れ後も未解決通報を失わないこと。
- 通報時点の証跡を公開Repositoryへ保存しないこと。
- 通報理由には少なくとも以下を含めること。
  - 危険運転・走行中撮影を疑う内容
  - 違法行為・違法改造の助長
  - 個人情報・生活拠点・正確位置
  - 人物、ナンバープレート、表札等の無断掲載
  - 著作権・商標・肖像等の権利侵害
  - 誹謗中傷・嫌がらせ
  - スパム・広告
  - その他

## 7. 状態モデル

### 7.1 ライフサイクル状態

| 状態 | 意味 | 主な遷移元 | 主な遷移先 |
| --- | --- | --- | --- |
| `DRAFT` | 投稿者だけが編集できる下書き | 新規 | `PUBLISHED`, `DELETED` |
| `PUBLISHED` | 公開済み。公開状態が`PUBLIC`の場合のみ閲覧可能 | `DRAFT` | `EXPIRED`, `DELETED` |
| `EXPIRED` | `expires_at`到達済み | `PUBLISHED` | 原則なし |
| `DELETED` | 投稿者削除要求済みまたは削除処理済み | `DRAFT`, `PUBLISHED` | 原則なし |

### 7.2 公開状態

| 状態 | 意味 |
| --- | --- |
| `PRIVATE` | 投稿者本人のみ閲覧可能 |
| `PUBLIC_REVIEW_REQUIRED` | 公開前確認中 |
| `PUBLIC` | 公開中。ただし期限内かつ停止されていない場合のみ |
| `STOPPED` | 運営、権利、安全、プライバシー等の理由で停止 |

### 7.3 優先順位

閲覧可否は次の順で判定する。

1. `STOPPED`なら非公開
2. `DELETED`なら非公開
3. `EXPIRED`または`now >= expires_at`なら非公開
4. 公開状態が`PUBLIC`以外なら一般閲覧者へ非公開
5. 投稿者・閲覧者の認可を確認
6. 参照先状態を確認
7. 問題がない場合のみ表示

### 7.4 公開期限

- `expires_at = published_at + 24 hours`とする。
- 保存・比較はUTC基準とする。
- UI表示は利用者のタイムゾーンへ変換する。
- 日本時間の日付変更、サーバー再起動、バッチ遅延等で24時間を延長しない。
- 期限判定を表示バッチだけに依存させず、閲覧時にも検証する。
- 期限到達後の公開停止SLOは後続非機能要件で確定する。

## 8. 入力項目

| 項目 | 必須 | 初期制約候補 | 補足 |
| --- | --- | --- | --- |
| 画像 | 原則必須 | JPEG / PNG、1件 | 文字だけ投稿可否は未確定 |
| 短文 | 任意 | 200文字以内候補 | URL、絵文字、改行の扱いは後続設計 |
| 参照リンク | 任意 | 1件 | 公開中かつ閲覧可能な対象のみ |
| 粗いエリア名 | 任意 | 都道府県・地方等 | 現在地自動付与は禁止 |
| 公開範囲 | 必須 | 初期値`PRIVATE` | 公開前確認必須 |

上限値は内部βで検証し、人間レビュー後に確定する。

## 9. 画像・位置情報要件

### 9.1 EXIF

- 公開前にEXIF等のメタデータを除去すること。
- 除去に失敗した画像は公開しないこと。
- 元画像を保持する場合の目的・期間・権限は後続の保持ポリシーで確定すること。
- 公開用派生画像から位置情報・端末情報等を復元できないことを確認すること。

### 9.2 映り込み

公開前確認で少なくとも以下を案内する。

- 人物・子ども
- ナンバープレート
- 表札・住所・郵便物
- 自宅・勤務先・車両保管場所
- 反射物に映る人物・車両・建物
- 鍵、カード、QRコード、チケット
- 未公開施設、私有地、立入禁止区域

自動ぼかしはMVP対象外とし、ユーザー確認と通報・停止運用を前提とする。

### 9.3 位置表示

- GPS・端末位置情報をストーリー作成時に自動取得しない。
- 正確な緯度経度をストーリー本文へ構造化保存しない。
- 公開スポット参照時も、ストーリー独自の正確位置コピーを作らない。
- 粗いエリア名はユーザーが選択する候補とし、現在地であることを示す文言を初期生成しない。
- 公開時刻とエリアの組み合わせによる現在地推定リスクを警告する。

## 10. 安全要件

- ストーリー作成・編集画面の先頭に「停車中または走行後に操作してください」を表示する。
- 走行中の撮影・投稿を推奨する文言、バッジ、連続投稿報酬を設けない。
- 走行速度、リアルタイム軌跡、現在地、運転操作と連動した投稿を行わない。
- 「今ここにいる」等の現在地共有を初期文言として提示しない。
- 危険運転・速度違反・無謀運転・違法改造等を称賛するランキングや推薦を行わない。
- ストーリーは道路状況・施設営業・通行可能性を保証する情報として扱わない。
- 閲覧画面でも走行中利用を促さない。

## 11. 権限・認可

- 下書き・非公開ストーリーは投稿者本人だけが閲覧・編集できること。
- 他ユーザーはストーリーを編集・削除・再公開できないこと。
- 管理者操作は権限分離・監査対象とすること。
- `STOPPED`を投稿者が解除できないこと。
- 参照先コンテンツの閲覧権限を毎回確認すること。
- URLを知っていても期限切れ・削除・停止済みストーリーを取得できないこと。
- CDNキャッシュ・画像URLから停止済み画像へ継続アクセスできない設計を後続で定義すること。

## 12. 表示・UX要件

### 12.1 作成画面

- 停車中・走行後利用の注意
- 画像選択
- 短文入力
- 参照リンク選択
- 粗いエリア選択
- 公開範囲
- EXIF除去結果
- 映り込み確認項目
- スクリーンショット等により期限後も残り得る注意

### 12.2 閲覧画面

- 投稿者
- 公開時刻または残り時間
- 画像・短文
- 粗いエリアまたは参照リンク
- 通報
- 非表示
- 停止・期限切れ時の一般化した案内

### 12.3 期限切れ表示

- 公開一覧、ホーム、プロフィール、直接URLから表示しない。
- 投稿者本人に期限切れ履歴を表示するかは未確定とする。
- 「24時間で完全削除」等の保証表現を使用しない。

## 13. 閲覧数・分析

MVPで閲覧数を提供する場合:

- 投稿者へは集計値のみ表示する候補とする。
- 個別閲覧者一覧は提供しない。
- 閲覧イベントの保持期間・匿名化・重複排除方法は後続設計で確定する。
- 管理・分析目的を超えた追跡を行わない。
- 閲覧数を危険運転や過度な投稿を促すランキングへ利用しない。

閲覧数自体を内部βで提供しない選択肢も維持する。

## 14. モデレーション・運用要件

- 通報受理後、期限切れになっても案件状態を維持する。
- 重大な安全・個人情報・権利侵害は公開停止を物理削除より先に行う。
- 投稿者への停止理由は、通報者情報を漏らさない一般化した内容とする。
- 誤停止・異議申立て・復旧の有無はモデレーションrunbookで確定する。
- 自動検査は補助とし、人間確認が必要な条件を定義する。
- 期限切れコンテンツを運用者が閲覧する権限、目的、監査ログを限定する。
- 公開前の全件人手審査を行うか、事後モデレーションとするかは内部β前に決定する。

## 15. 保持・削除要件

### 15.1 確定事項

- 24時間は公開表示期間であり、物理保持期間ではない。
- 期限到達時に一般閲覧を停止する。
- 投稿者削除要求時は公開表示を先に停止する。
- 未解決通報・法的保全・監査証跡を期限切れだけで破棄しない。
- 保持データへアクセスできる主体・目的を制限する。

### 15.2 未確定事項

- 期限切れ画像・本文の通常保持期間
- 投稿者削除時の物理削除SLA
- 通報案件の証跡保持期間
- バックアップ・キャッシュからの削除SLA
- 投稿者向けアーカイブの有無
- 復元可能期間の有無

これらは法務・プライバシー・セキュリティ・運用レビュー後に別Issueで確定する。

## 16. 非機能要件

### 16.1 性能

- 公開中ストーリー一覧の目標件数・ページング方式を後続設計で定義する。
- 画像最適化・派生画像作成に失敗した場合は公開しない。
- 期限切れ判定は閲覧要求時にも実施する。
- 大量アクセス時も期限切れ・停止済みコンテンツを返さない。

### 16.2 可用性

- ストーリー機能障害時に通常投稿、走行記録、スポット等を巻き込まない。
- 期限処理バッチ停止時も閲覧時判定で公開期限を超えない。
- 画像配信停止時は代替テキストまたは利用不可表示とし、古いキャッシュを無制限表示しない。

### 16.3 セキュリティ

- ファイル拡張子だけでなく実体形式を検査する。
- 画像サイズ・容量・デコード可否を検証する。
- 悪意あるファイル、スクリプト、ポリグロット等を考慮する。
- 非公開・期限切れ・停止済み画像へ署名なし固定URLでアクセスできないようにする候補とする。
- 所有者認可、管理者権限、通報閲覧権限を分離する。
- 主要状態変更を監査ログへ記録する。

### 16.4 プライバシー

- 取得データを機能提供・安全・通報対応に必要な範囲へ限定する。
- 閲覧者一覧を提供しない。
- 現在地自動取得を行わない。
- EXIF除去失敗時は公開しない。
- 公開時刻と地域表示による行動推定リスクを説明する。

## 17. 画面要件

新規画面候補:

- `SCR-25`: ドライブストーリー作成・公開前確認
- `SCR-26`: ドライブストーリー閲覧
- `SCR-27`: 自分のドライブストーリー管理

既存画面更新候補:

- `SCR-05`: 公開中ストーリー導線・自分の作成導線
- `SCR-13`: コミュニティ投稿とストーリーの責務分離
- `SCR-17`: ストーリー通報対象追加
- `SCR-19`: ストーリーミュート・公開既定値の設定候補

## 18. API・データ境界候補

本IssueではAPI・DBを確定しないが、後続設計で最低限分離する責務を示す。

- Story lifecycle
- Story visibility
- Story media
- Story reference
- Story report
- Story hide / mute
- Story expiration
- Story moderation stop
- Story audit

公開期限処理、画像配信、通報証跡を単一の画面ロジックへ集約しない。

## 19. 対象外

- 動画・音声ストーリー
- ライブ配信
- リアルタイム現在地共有
- 走行中の自動投稿
- 返信、DM、コメント、絵文字リアクション
- 閲覧者一覧
- フォロー限定公開
- 外部SNSへの自動共有
- BGM、スタンプ、フィルター等の高度編集
- 自動ぼかし・高度画像編集
- 広告、課金、プロモーション
- 推薦・ランキングアルゴリズム
- WebSocket等のリアルタイム方式決定
- DB/API/画像ストレージ/CDN/UI実装

## 20. 受け入れ条件

- 24時間の起算点とUTC基準の期限判定が定義されている。
- 期限切れと物理削除・内部保持が分離されている。
- 公開状態とライフサイクル状態が分離されている。
- `STOPPED`の優先順位が定義されている。
- 通常投稿、走行記録、ストーリーの責務が分離されている。
- 現在地自動付与・正確座標公開が禁止されている。
- EXIF除去失敗時のNo-Goが定義されている。
- 参照先停止時の権限・表示境界が定義されている。
- 通報案件が期限切れで消失しない。
- 停車中または走行後の利用制約が定義されている。
- 返信、DM、リアクション、閲覧者一覧等が対象外として維持されている。
- 実装・実画像・実位置情報を扱っていない。

## 21. テスト観点

### 21.1 正常系

- 下書きを作成・編集・破棄できる。
- 公開前確認後に公開できる。
- `published_at`から24時間以内に閲覧できる。
- 期限前に非公開化・削除要求できる。
- 期限到達後に公開一覧・直接URLから閲覧できない。
- 公開スポット・走行記録・車両プロフィールを参照できる。
- 通報・個別非表示・ミュート候補が機能する。

### 21.2 異常系

- EXIF除去失敗画像を公開する。
- ファイル形式偽装画像を受け付ける。
- 現在地を自動添付する。
- 他ユーザーの下書き・非公開ストーリーを取得する。
- 期限切れ・削除・停止済みURLから画像を取得する。
- `STOPPED`を投稿者が解除する。
- 非公開参照先をストーリー経由で閲覧する。
- 未解決通報を期限切れとともに削除する。
- 24時間を物理削除保証として案内する。

### 21.3 境界値

- 公開時刻ちょうど。
- 23時間59分59秒。
- 24時間ちょうど。
- 24時間0分1秒。
- UTC日付変更、日本時間日付変更。
- サーバー時刻ずれ・再起動・バッチ停止。
- 画像0件、1件、上限超過。
- 短文0文字、200文字候補、上限超過、絵文字、改行。
- 期限到達と削除・停止・通報が同時発生。
- 参照先が公開直後に停止する。

### 21.4 回帰

- 本格SNS機能をMVPへ混入させない。
- 走行中操作禁止を弱めない。
- 自宅周辺ぼかし・位置情報最小化を弱めない。
- 参照先の閲覧権限を復活させない。
- 全公開コンテンツから通報導線を維持する。
- ストーリー障害が通常投稿・走行記録へ波及しない。
- 実画像・実位置情報を公開Repositoryへ保存しない。

### 21.5 セキュリティ

- IDORにより他ユーザーの下書きを取得できない。
- 期限切れ画像URLを再利用できない。
- 管理者権限なしで停止解除できない。
- ファイル形式・容量・デコード検査を回避できない。
- CDN・キャッシュが停止状態を無視しない。
- 監査ログへ機密本文・画像を過剰記録しない。

### 21.6 運用

- 期限切れ前後の通報を継続処理できる。
- 公開停止を削除より先に実施できる。
- 停止理由を通報者情報なしで投稿者へ案内できる。
- 保持期限到達時の削除対象を抽出できる。
- バッチ停止時も期限超過公開を防止できる。

## 22. リスクと対策

| リスク | 対策 |
| --- | --- |
| 走行中投稿の誘発 | 停車中・走行後の明示、報酬・リアルタイム連携禁止 |
| 現在地・生活拠点推定 | 自動位置取得禁止、粗い地域のみ、公開時刻との組み合わせ警告 |
| EXIF漏えい | 公開前除去、失敗時No-Go |
| 映り込み | 公開前チェック、通報・停止、将来のぼかし検討 |
| 期限超過表示 | UTC期限、閲覧時判定、バッチだけに依存しない |
| 期限切れ後の通報消失 | 通報案件と公開ライフサイクルを分離 |
| 参照先権限の復活 | 参照時認可、停止・非公開時リンク解除 |
| CDN残存 | 後続設計で署名URL・キャッシュ失効・削除SLAを定義 |
| SNS機能肥大化 | 返信・DM・リアクション・フォロー・動画等を対象外に固定 |
| モデレーション負荷 | 内部β、投稿上限候補、停止優先、runbook整備 |
