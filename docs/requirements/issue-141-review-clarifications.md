## 2. 月・年所属を決める日付

### TIME-INV-01: MVPの集計所属は`走行日`で固定する

MVPの走行記録は、ユーザーが実績として保存した**日付のみの業務項目「走行日」**を月・年・日数集計の正本とする。

例:

- 走行日 `2026-08-31` → 2026年8月に所属
- 走行日 `2026-09-01` → 2026年9月に所属

### TIME-INV-02: システムtimestampで再分類しない

次を月・年所属の判定に使用しない。

- `created_at`
- `updated_at`
- API受信時刻
- ブラウザ閲覧時刻
- サーバー実行時刻

### TIME-INV-03: 閲覧環境やタイムゾーン設定変更で過去記録を移動させない

保存済みの`走行日`が変わらない限り、閲覧端末や将来のユーザータイムゾーン設定が変化しても、既存記録の月・年所属を変更しない。

### TIME-INV-04: 再分類は走行日訂正時だけ

ユーザーが走行記録の`走行日`自体を訂正した場合は、旧日付の期間と新日付の期間の双方を再集計する。

### TIME-INV-05: 将来datetimeへ拡張する場合は別要件

将来、走行開始/終了datetime等を導入して統計所属へ利用する場合は、タイムゾーン取得・保存・変更・DST・過去再分類の方針を別要件で承認する。

Issue #141の承認だけでdatetimeベースへ変更しない。

## 3. 公開投稿経由の統計漏えい防止

### AUTH-TEST-05: 公開投稿正常閲覧

本人以外が閲覧可能な公開投稿の正常レスポンス、serialized props、client state、prefetchデータに、本人限定の統計値を含めないことを必須テストとする。

含めてはならない例:

- 月間/年間走行距離
- ドライブ回数
- 平均/最長走行距離
- 記録のある日数
- 車両別統計
- 最終利用日
- 訪問履歴/訪問集計
- コレクション達成履歴/進捗
- 頻出エリア候補

### AUTH-TEST-06: 公開経路を個別に検証する

以下は別々の正常閲覧テストとして扱う。

1. 公開プロフィール
2. 公開投稿
3. 公開ストーリー

「統計APIのID直指定を拒否できる」だけでは上記公開経路の非漏えい確認を代替しない。

## 4. 距離あり・未入力混在時の表示

### DIST-DISPLAY-INV-01: 一部距離ありの場合は有効統計を表示する

対象期間に、

- 距離入力済み有効走行記録
- 距離未入力の有効走行記録

が混在する場合、距離入力済み記録から算出可能な距離統計は表示する。

表示対象候補:

- 合計走行距離
- 平均走行距離
- 最長ドライブ距離

同時に、**「距離未入力の記録があります」**等の欠損注記を表示する。

### DIST-DISPLAY-INV-02: 全件未入力の場合だけ距離データなし

対象期間の有効走行記録が1件以上存在していても、距離入力済み有効記録が0件の場合のみ、距離系指標を「距離データなし」または「算出できません」とする。

`0 km`とは表示しない。

### DIST-DISPLAY-INV-03: 0kmは実値の場合だけ

距離が明示的に`0 km`として保存された有効記録は、未入力とは区別する。

### DIST-DISPLAY-INV-04: 回数は距離欠損の影響を受けない

距離未入力でも走行記録自体が有効なら、ドライブ回数には含める。

## 5. 車両参照解除時の再集計

### VEHICLE-DERIVED-INV-01: 車両Aから車両Bへ変更

旧車両Aと新車両Bの双方について、影響する統計を再評価する。

候補:

- ドライブ回数
- 合計/平均/最長距離
- 最終利用日
- 期間内利用車両数

### VEHICLE-DERIVED-INV-02: 車両参照を解除してnullに変更

旧車両について上記統計を再評価する。

新車両は存在しないため、解除後の記録をいずれかの車両へ推測配分しない。

### VEHICLE-DERIVED-INV-03: nullから車両へ設定

新しく設定された車両について影響統計を再評価する。

### VEHICLE-DERIVED-INV-04: キャッシュ/派生値を残さない

車両参照の変更・解除後に、旧車両の回数・距離・最終利用日・利用車両数等の古い派生値を残さない。

## 6. 追加必須テスト

### 期間所属

- `2026-08-31`は8月だけに所属する
- `2026-09-01`は9月だけに所属する
- created_atが翌月でも走行日が前月なら走行日側の月に所属する
- 閲覧端末のタイムゾーン変更で所属月が変わらない
- 走行日訂正時は旧月・新月双方を再評価する

### 認可

- 公開プロフィール正常閲覧で統計非露出
- 公開投稿正常閲覧で統計非露出
- 公開ストーリー正常閲覧で統計非露出

### 距離欠損

- 距離あり1件 + 距離未入力1件 → 距離統計を算出し、欠損注記を併記
- 距離未入力のみ → 距離系はデータなし/算出不能
- 0km明示1件 → 未入力と区別

### 車両参照

- A → B変更でA/B双方を再集計
- A → null解除でAを再集計し、記録を他車両へ配分しない
- null → B設定でBを再集計

## 7. Codex指摘対応一覧

1. P1 月所属タイムゾーン未定義 → 日付のみの`走行日`をMVP正本として固定し、閲覧タイムゾーンによる再分類を禁止。
2. P1 公開投稿経由の漏えいテスト不足 → 公開投稿を独立した必須正常閲覧テストへ追加。
3. P2 距離あり/未入力混在時の表示 → 算出可能値を表示し欠損注記を併記。全件未入力時のみ距離データなし。
4. P2 車両参照解除時の再集計 → A→null/null→Bを明示し、旧車両の派生値再評価を必須化。
