# ドライブコレクション・訪問進捗機能 要件定義

## 1. 文書情報

- 対象Issue: #132
- 対象フェーズ: Phase 1 / Requirements Definition
- 対象プロダクト: RouteGarage Web MVP拡張候補
- 状態: 人間レビュー待ち
- 実装: 対象外

## 2. 目的

RouteGarage内のスポットをテーマ別にまとめた`ドライブコレクション`を提供し、ユーザーが「次にどこへ行くか」を見つけ、保存し、ドライブプランへ追加し、走行後に訪問進捗を記録できる要件を定義する。

本機能はランキングや速度競争ではなく、出発前の発見と走行後の振り返りを強化することを目的とする。

## 3. 基本方針

- 初期リリースではRouteGarage運営が編集するコレクションのみを対象とする。
- ユーザー生成コレクションは対象外とする。
- コレクションは既存スポットを参照し、スポット本文・画像・正確位置を恒久複製しない。
- 訪問記録はユーザーの自己申告とし、運営による訪問証明として扱わない。
- GPS、ジオフェンス、常時位置取得を訪問証明として要求しない。
- 走行記録を参照できるが、自動的に訪問済みへ確定しない。
- 訪問登録、取消、メモ、プラン追加は停車中または走行後に行う。
- ランキング、最速達成、速度、距離競争、ストリークを導入しない。
- 保存状態、訪問履歴、達成記録の初期公開範囲は本人限定とする。
- 元スポットの停止・削除・非公開化・権利停止・安全停止をコレクション経由で回避しない。
- AIだけでコレクション公開、スポット採用、権利・安全判定を確定しない。

## 4. 対象ユーザー

- 行き先をテーマから探したいユーザー
- 複数のスポットを少しずつ巡りたいユーザー
- 過去に巡った場所を個人記録として見返したいユーザー
- 競争ではなく自分のペースで達成を楽しみたいユーザー

## 5. 用語・責務

| 用語 | 責務 |
| --- | --- |
| ドライブコレクション | RouteGarage運営がテーマ別に既存スポットをまとめる編集コンテンツ |
| コレクション項目 | コレクションから既存スポットへの参照 |
| 保存コレクション | ユーザーが後で見返すために保存したコレクション |
| 訪問記録 | ユーザーが特定スポットを訪問したと自己申告する個人記録 |
| 走行記録参照 | 訪問記録から本人の走行記録へ任意で関連付ける参照 |
| 進捗 | 特定コレクション版に対する訪問数・対象数・達成状態 |
| 達成記録 | 特定コレクション版の完了を記録する個人記録 |
| コレクション版 | 対象スポット構成が変化した単位を識別する版 |

`行きたいスポット`は個人ブックマーク、`ドライブプラン`は出発前予定、`走行記録`は実績、`訪問記録`はコレクション進捗用の自己申告として責務を分ける。

## 6. コンテンツ種別

### 6.1 初期テーマ候補

実際のスポット名・画像・説明文は本Issueでは投入しない。テーマ分類のみ定義する。

- 絶景・景観
- 道の駅
- PA / SA
- 温泉
- 展望台
- ダム・橋
- ご当地グルメ
- カフェ
- 夜景
- 季節ドライブ
- 海沿い
- 山・高原
- 歴史・文化

### 6.2 コレクション基本項目

| 項目 | 必須 | 初期方針 |
| --- | --- | --- |
| タイトル | 必須 | 運営編集 |
| 概要 | 必須 | 運営独自記述 |
| テーマ | 必須 | 管理された分類 |
| 対象エリア | 必須 | 都道府県・地方等の粗い単位 |
| カバー画像 | 任意 | 権利確認済み素材のみ |
| 注意事項 | 任意 | 季節・施設状態・安全等 |
| 項目一覧 | 必須 | 既存スポット参照 |
| 表示順 | 必須 | 運営編集 |
| content_revision | 必須 | 構成変更を識別 |
| reviewed_at | 必須候補 | 公開内容確認日時 |
| recheck_due_at | 条件付き | 季節・鮮度依存時 |

## 7. コレクション状態

### 7.1 状態

- `DRAFT`: 編集中
- `REVIEW_REQUIRED`: 公開前または重要変更後のレビュー待ち
- `PUBLISHED`: 公開中
- `STOPPED`: 権利、安全、プライバシー、運用等による停止
- `ARCHIVED`: 新規利用を終了した過去コレクション

### 7.2 優先順位

1. `STOPPED`
2. `ARCHIVED`
3. `REVIEW_REQUIRED`
4. `DRAFT`
5. `PUBLISHED`

一般ユーザーが新規保存・進捗開始できるのは原則`PUBLISHED`のみとする。

### 7.3 公開条件

`PUBLISHED`へ進むには少なくとも以下を満たす。

- タイトル、概要、テーマ、対象エリアが確定している
- 1件以上の有効な公開スポットを参照している
- 参照スポットの権利・安全・公開状態を確認している
- カバー画像を使う場合は権利状態を確認している
- 季節依存・施設依存情報の鮮度を確認している
- 走行中操作を促す表現がない
- 最速、順位、競争を促す表現がない
- コンテンツレビューを完了している

## 8. コレクション版管理

### 8.1 目的

公開後にスポット追加・削除・停止が発生しても、過去の達成記録を不整合にしないため、対象スポット構成を`content_revision`で識別する。

### 8.2 版を上げる変更

少なくとも以下は新しい`content_revision`とする。

- 対象スポット追加
- 対象スポット削除
- 対象スポット差し替え
- 達成条件に影響する有効対象数変更

タイトルの誤字修正など、達成条件へ影響しない変更は同一版内の編集候補とする。

### 8.3 過去達成の扱い

- 達成記録は`collection_id`と`content_revision`へ紐づける。
- 新版公開後も旧版の達成事実を削除しない。
- 新版では現在の対象構成に基づき進捗を別計算する。
- UIで必要な場合は「旧版達成」等、現在版との違いが分かる表示を行う。
- 削除・権利停止されたスポットの本文、画像、正確位置を過去達成画面へ復元表示しない。
- 過去達成には必要最小限の版・件数・達成日時のみ保持する候補とする。

## 9. 保存機能

- 公開中コレクションを保存・解除できること。
- 同一ユーザー・同一コレクションの有効保存は1件とする。
- 保存状態は本人限定とする。
- `STOPPED`後は新規保存できないこと。
- `ARCHIVED`後の既存保存表示は履歴用途として候補とするが、新規進捗開始は不可とする。
- 保存解除しても訪問記録・達成記録を自動削除しない。

## 10. 訪問記録

### 10.1 状態

コレクション内地点のユーザー状態は次を候補とする。

- `NOT_VISITED`
- `VISITED`
- `UNAVAILABLE`

`UNAVAILABLE`はユーザー入力ではなく、元スポット停止等によるシステム表示状態とする。

### 10.2 訪問登録

- ユーザーは閲覧可能な対象スポットを訪問済みにできること。
- 訪問登録は停車中または走行後に行うこと。
- 訪問日時は任意とする。
- 所有者限定メモを任意で設定できること。
- 本人の閲覧可能な走行記録を任意で1件以上参照できる候補とする。
- 走行記録を参照しても訪問済みへ自動確定しない。
- 訪問記録は自己申告であることを表示できること。
- 訪問済みを取り消せること。
- 取消履歴を監査対象とするかは後続設計で確定する。

### 10.3 訪問記録の由来

訪問記録の入力由来を少なくとも次で区別する候補とする。

- `MANUAL`: ユーザーが手動で訪問済み登録
- `DRIVE_RECORD_REFERENCE`: 本人の走行記録を参照して明示的に登録

どちらも運営確認済み訪問を意味しない。

## 11. 進捗計算

### 11.1 基本値

- `visited_count`: 現在版で訪問済みと評価できる有効対象数
- `eligible_count`: 現在版の達成対象となる有効対象数
- `progress_rate = visited_count / eligible_count`

`eligible_count = 0`の場合は0%または達成不能状態として扱い、100%にしない。

### 11.2 進捗状態

- `NOT_STARTED`: `visited_count = 0`
- `IN_PROGRESS`: `0 < visited_count < eligible_count`
- `COMPLETED`: `eligible_count > 0`かつ`visited_count = eligible_count`

### 11.3 元スポット停止時

元スポットが非公開・削除・権利停止・安全停止になった場合:

1. コレクション上で元本文・画像・正確位置を表示しない。
2. 該当項目を`UNAVAILABLE`として扱う。
3. 新規訪問登録を停止する。
4. 過去のユーザー訪問記録自体は直ちに削除しない。
5. 現在版の`eligible_count`から除外するか、コレクション版を停止・改訂するかは運営レビュー対象とする。
6. 判断不能な場合はコレクションを`REVIEW_REQUIRED`または`STOPPED`へ遷移する。

安全・権利停止を「達成しやすくするための自動分母減少」として処理しない。

## 12. 達成記録・記念バッジ

### 12.1 達成記録

- 特定`content_revision`で`COMPLETED`となった時点を記録できること。
- `completed_at`を保持する候補とする。
- 同一版に対する達成記録の重複生成を防ぐこと。
- 達成後に訪問取消した場合の状態は後続設計で確定する。
- 過去達成と現在版未達成を同時に表現できること。

### 12.2 記念バッジ

内部βでは個人用表示のみを推奨する。

候補表示:

- コレクション名
- 達成版
- 達成日
- 記念アイコン

公開する場合も次を自動公開しない。

- 訪問日時一覧
- 訪問順序
- 正確位置
- 走行ルート
- 速度・所要時間

### 12.3 禁止する競争要素

- 最速達成
- 最短時間
- 最長距離
- 最高速度
- 順位
- 県内1位等のランキング
- 連続日数ストリーク
- 危険運転を誘発する期限付き競争

## 13. 行きたいスポットとの接続

- コレクション詳細から各対象スポットを`行きたい`へ保存できること。
- すでに保存済みの場合は重複保存しないこと。
- 元スポット停止時は既存の行きたいスポット要件を継承すること。
- コレクション保存と行きたいスポット保存を同一エンティティにしないこと。

## 14. ドライブプランとの接続

- コレクション詳細から未訪問スポットをドライブプランへ追加できる候補とする。
- 全スポット一括追加は地点数上限、安全性、操作負荷を確認して後続設計で判断する。
- コレクション表示順を推奨ルートや安全な経路と表現しない。
- 地点順は既存ドライブプラン要件に従いユーザーが手動で決定する。
- コレクションから追加しても通行可能性・所要時間を保証しない。

## 15. 走行記録との接続

- 訪問記録から本人の走行記録を参照できること。
- 走行記録側から訪問候補を提案するかは後続候補とする。
- 位置・日時一致だけで訪問済みへ自動確定しない。
- 非公開走行記録の内容を公開コレクション画面へ表示しない。
- 走行記録削除後は参照を解除し、訪問記録の自己申告部分をどう扱うかは後続設計で確定する。

## 16. コンテンツ権利・鮮度・運用

### 16.1 運営独自情報

RouteGarageが独自作成する候補:

- コレクションタイトル
- 独自概要
- テーマ分類
- 表示順
- 編集上の注意事項

第三者文章をコピーして作成しない。

### 16.2 スポット由来情報

- 名称、画像、位置、施設情報等は元スポットの権利・公開状態を継承する。
- コレクションへ恒久コピーして権利停止を回避しない。
- 元情報停止時は参照表示を停止する。

### 16.3 カバー画像

利用可能なのは少なくとも次のいずれかに限定する。

- RouteGarageが権利を保有する画像
- 利用許諾を確認済みの画像
- 公開条件・加工条件・帰属を確認済みの素材

権利不明画像を仮素材として公開しない。

### 16.4 鮮度

季節・営業・通行条件等へ依存するコレクションは:

- `reviewed_at`
- 必要に応じて`recheck_due_at`
- 注意事項

を管理する候補とする。

再確認期限を過ぎた場合、現在有効と断定せず`REVIEW_REQUIRED`または表示制限を候補とする。

## 17. 安全要件

- 訪問登録、取消、メモ、プラン追加は停車中または走行後に行う。
- 走行中のチェックイン操作を促さない。
- コレクションの完全制覇を短時間で行うことを促さない。
- 危険地点・立入禁止場所・道路上で停車が必要な地点を安易に対象化しない。
- コレクション掲載を「安全」「通行可能」「駐車可能」の保証としない。
- 現地標識、道路管理者、施設管理者等の指示を優先する。
- 季節・時間帯・天候で危険性が変わる場合は注意事項と再確認を必須候補とする。

## 18. プライバシー要件

- 訪問履歴は本人限定を初期値とする。
- 訪問日時は任意とする。
- 正確な現在地・移動軌跡をコレクション機能のために追加取得しない。
- 自宅、勤務先、車両保管場所等をコレクション対象として扱わない。
- 達成記録公開を導入しても訪問日時・順序・正確位置を自動公開しない。
- 他ユーザーの訪問履歴を取得・推定できないこと。
- 走行記録参照の認可を毎回確認すること。

## 19. セキュリティ・認可要件

- 保存、訪問記録、メモ、達成記録は本人だけが更新できること。
- 他ユーザーの非公開進捗を取得できないこと。
- 運営編集権限と一般ユーザー権限を分離すること。
- `STOPPED`を一般編集操作で解除できないこと。
- コレクション項目参照時に元スポットの閲覧権限・公開状態を確認すること。
- ID直指定で停止済み・非公開情報を取得できないこと。
- 主要な公開・停止・版更新操作を監査対象とすること。

## 20. 画面要件

### SCR-28 ドライブコレクション一覧

目的:

- テーマから次のドライブ候補を発見する。

表示候補:

- タイトル
- テーマ
- 対象エリア
- 対象スポット数
- 保存状態
- 本人の進捗率
- 最新レビュー状態または注意表示

操作:

- 絞り込み
- コレクション詳細へ
- 保存・解除

### SCR-29 ドライブコレクション詳細

目的:

- コレクション内容・進捗・注意事項を確認する。

表示候補:

- タイトル、概要、テーマ、対象エリア
- 対象スポット一覧
- 各地点の訪問状態
- 進捗
- 注意事項
- 版情報候補
- 停止・再確認状態

操作:

- 保存・解除
- スポット詳細へ
- 行きたいへ追加
- ドライブプランへ追加
- 訪問済み登録・取消
- 自分の進捗詳細へ

### SCR-30 自分のコレクション進捗

目的:

- 保存中・進行中・達成済みコレクションを個人記録として見返す。

表示候補:

- 保存コレクション
- 現在版進捗
- 過去達成版
- 訪問日時（本人のみ）
- 個人メモ
- 走行記録参照
- 記念バッジ候補

操作:

- 訪問記録編集
- 走行記録参照追加・解除
- 保存解除
- コレクション詳細へ

## 21. 主要導線

### 21.1 発見

`ホーム / スポット探索 -> SCR-28 -> SCR-29`

### 21.2 計画

`SCR-29 -> 行きたいスポット -> SCR-23 ドライブプラン作成/編集`

または

`SCR-29 -> SCR-23 ドライブプラン作成/編集`

### 21.3 走行後

`走行後 -> SCR-29 / SCR-30 -> 訪問済み登録 -> 必要に応じて走行記録参照`

### 21.4 達成

`訪問登録 -> 進捗再計算 -> 現在版全対象達成 -> 達成記録生成候補 -> SCR-30`

## 22. 対象外

- GPS位置証明
- ジオフェンス自動チェックイン
- リアルタイム位置共有
- ランキング
- 最速・速度・距離競争
- ストリーク
- 賞金・景品・抽選
- NFT等の外部資産化
- ユーザー生成コレクション
- リアルタイム共同編集
- 外部観光DB・施設APIの採用決定
- 実在スポット・実画像の投入
- DB / API / UI / Storage / CDN実装

## 23. 未確定事項

- コレクション1件あたりの最大スポット数
- テーマ複数選択可否
- コレクション保存上限
- 訪問日時の粒度
- 訪問取消後の達成記録扱い
- `UNAVAILABLE`地点と達成分母の最終ルール
- 版更新後の現在進捗UI
- 過去版閲覧範囲
- 記念バッジの公開可否
- 内部βでバッジ自体を有効化するか
- カバー画像の仕様
- コンテンツ再確認周期
- 季節限定コレクションの公開期間
- 運営編集・レビュー権限モデル

## 24. 受け入れ条件

- [ ] コレクション、訪問進捗、達成記録の責務が分離されている。
- [ ] 既存スポットを参照し、停止時の情報復活を防止している。
- [ ] 行きたい、プラン、走行記録との接続境界が定義されている。
- [ ] GPS証明を必須にしていない。
- [ ] 訪問記録を自己申告として扱っている。
- [ ] ランキング・速度競争を対象外としている。
- [ ] コレクション版と過去達成の扱いが定義されている。
- [ ] 元スポット停止時の進捗・公開再レビュー条件がある。
- [ ] コンテンツ権利・鮮度・カバー画像の公開ゲートがある。
- [ ] 公開初期値・認可・監査境界がある。
- [ ] 安全・プライバシー要件がある。
- [ ] 正常・異常・境界・回帰・安全・セキュリティ・運用テスト観点がある。
- [ ] 実装・実データ投入・外部送信へ進んでいない。
- [ ] AI生成物の人間レビューが必須である。

## 25. テスト・確認観点

### 25.1 正常系

- 公開コレクションを一覧・詳細表示できる。
- 保存・解除できる。
- 行きたいスポットへ追加できる。
- ドライブプランへ追加できる。
- 訪問済み登録・取消ができる。
- 所有者限定メモを保存できる。
- 本人の走行記録を任意参照できる。
- 訪問数、対象数、進捗率を確認できる。
- 全対象達成時に現在版を`COMPLETED`として扱える。
- 新版公開後も旧版達成が保持される。

### 25.2 異常系

- `STOPPED`コレクションを新規保存する。
- `REVIEW_REQUIRED`を一般公開する。
- 停止済みスポット本文・画像をコレクション経由で表示する。
- 他ユーザーの非公開訪問記録を取得する。
- 非公開走行記録を公開画面へ表示する。
- GPS許可を必須にする。
- 自己申告を運営確認済みとして表示する。
- `STOPPED`を一般編集者が解除する。
- 権利不明カバー画像を公開する。
- `eligible_count = 0`を100%達成とする。

### 25.3 境界値

- 対象地点0件、1件、上限件数。
- 訪問0件、1件、全件。
- 元スポット1件停止、複数停止、全件停止。
- 訪問登録と元スポット停止が同時に発生。
- 完了直前・完了直後に新版が公開される。
- 達成直後に対象地点が停止する。
- 訪問取消と達成記録生成が競合する。
- 同一地点を複数コレクションが参照する。
- 同一走行記録を複数訪問記録が参照する。

### 25.4 回帰

- 走行中操作禁止を弱めない。
- リアルタイム位置共有をMVPへ混入させない。
- 行きたいスポットの重複保存ルールを壊さない。
- ドライブプランを推奨経路へ変質させない。
- 走行記録の実績責務を壊さない。
- ストーリー・通常投稿を訪問証明へ自動利用しない。
- 元スポット停止時の閲覧権限を復活させない。
- 公開Repositoryへ実位置・実訪問履歴・非公開情報を保存しない。

### 25.5 安全・プライバシー

- 走行中チェックインを促す導線がない。
- 速度・順位・最短時間を表示しない。
- 訪問日時・順番・正確位置を公開しない。
- 自宅等の生活拠点を対象化しない。
- 停止・危険スポットを達成目的で訪問させる表示をしない。

### 25.6 運用

- コレクション公開前レビューが記録される。
- 構成変更時に`content_revision`が更新される。
- 重要変更後に再レビューされる。
- カバー画像の権利確認状態を追跡できる。
- 季節依存コンテンツの再確認期限を追跡できる。
- 元スポット停止時にコレクションを再評価できる。
