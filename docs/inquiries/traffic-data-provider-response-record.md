## 3. 回答ステータス

各項目を次のいずれかで記録する。

- `確認済み`: 書面回答または適用文書により確認できた
- `条件付き確認`: 条件を満たす場合のみ確認できた
- `未回答`: 回答がない
- `不明確`: 回答が曖昧、前提・文書版・責任主体が不明
- `非許可`: 明示的に許可されない
- `非対象`: 当該構成では使用しない

## 9. 回答の信頼性確認

- [ ] 公式窓口からの回答である
- [ ] 回答者の部署・権限を確認した
- [ ] 書面または正式資料がある
- [ ] 適用文書と版を特定した
- [ ] 回答の前提条件を特定した
- [ ] 製品紹介と契約許諾を分離した
- [ ] 口頭回答を正式回答として扱っていない
- [ ] 回答内容に矛盾がない
- [ ] 未回答・曖昧回答をGo扱いしていない
- [ ] 法務・運用・セキュリティ担当が確認した

## 10. Go / No-Go判定

### 必須ゲート

次をすべて満たす場合のみ、基本設計の候補へ進める。

- [ ] 契約主体と適用契約を特定できる
- [ ] 日本国内の対象地域・情報種別を確認できる
- [ ] 利用者への表示・公衆送信が許可される
- [ ] 必要な加工・状態判定が許可される
- [ ] 採用予定地図との重畳が許可される
- [ ] キャッシュ・保存・削除義務を実装・運用できる
- [ ] 上流由来・更新時刻・訂正・撤回を追跡できる
- [ ] 帰属・エンドユーザー条項を実装できる
- [ ] 障害・規約変更・契約停止時に提供停止できる
- [ ] 監査・問い合わせ・事故対応の証跡を保持できる
- [ ] 位置情報・個人データのプライバシー要件を満たせる
- [ ] 走行安全・取締り回避防止要件を弱めない
- [ ] 法務・運用・セキュリティ・プロジェクト責任者が承認した

### 判定

- 最終判定: `Go候補 / 条件付きGo候補 / No-Go / 保留`
- 判定日:
- 判定者:
- 条件:
- No-Go理由:
- 再評価条件:
- 関連Issue / ADR:

`Go候補`は採用決定ではない。データ提供元・地図基盤・アーキテクチャの採用時は別IssueとADRを作成する。

## 11. 証跡保存

保存対象:

- 送信した問い合わせ本文
- 送信日時・送信者・送信先
- 自動返信・受付番号
- 提供元回答
- 添付資料
- 適用規約・契約・SLAの版
- 内部レビュー記録
- 追加質問・回答
- Go / No-Go判定記録

提供元回答に転載・二次利用制限がある場合、Repositoryへ回答本文を公開しない。アクセス制御された保管先と、Repository上の要約・参照IDを分離する。
