## Issue #115 Current Gates

### データ分類・系譜

- 取得原本、正規化・加工後、表示用、履歴、キャッシュ、バックアップ、監査メタデータ、削除墓標を別分類で扱う。
- `lineage_root_id`と`artifact_id`で原本から派生物・公開物まで追跡する。
- 原本ハッシュ、派生物ハッシュ、変換版、権利台帳`record_id`を関連付ける。
- 系譜欠損時は表示・履歴・共有・エクスポートNo-Go。

### 保持判断

- 保存目的、利用方法別の許可、保持期限、再確認期限、承認者を保持開始前に記録する。
- 具体的保持期間はprovider・契約・権利・技術構成の確定後に決定する。
- 期限値・根拠・承認者のいずれかがない場合はNo-Go。
- 監査目的を理由にデータ本体を無期限保存しない。

### 削除・停止

- 権利・安全・真正性に疑義がある場合、物理削除より先に表示停止する。
- 原本削除を派生物、履歴、キャッシュ、インデックス、バックアップ、外部保存先へ伝播する。
- 論理削除だけで完了扱いにしない。
- 部分失敗は未完了として再試行・エスカレーションする。
- 削除処理失敗を理由に対象データを再表示しない。

### バックアップ・復旧

- バックアップ最大残存期間を保持開始前に定義する。
- 削除期限を満たせないバックアップ方式はNo-Go。
- 復旧時に削除墓標・停止台帳・権利台帳の最新状態を再適用する。
- 削除済みデータをキャッシュ・復旧処理から再公開しない。

### 監査・プライバシー

- データ本体と監査メタデータを分離する。
- 原本内容、正確位置、走行履歴、秘密情報、非公開回答本文を監査メタデータへ含めない。
- 削除墓標は再混入防止・削除完了説明に限定する。
- 墓標へデータ内容を保存しない。
- 監査メタデータ・墓標にも保持期限を設ける。

### 法的保全

- 法務承認、目的、範囲、期限、アクセス制御、削除計画を必須とする。
- `LEGAL_HOLD`は公開・加工・再利用を許可しない。
- 削除義務との競合は法務判断完了までNo-Go。
