## Review Findings

### 走行中操作・通知

- 車両停止時を除く画面注視・操作を前提にしない。
- 詳細確認・入力・再読込は安全な場所へ停車後に行う。
- 走行中のプッシュ通知・画面ポップアップ等、視覚・タップ操作を誘発する通知は`MVP禁止`。
- 正確地点接近時の音声通知は`要専門確認`かつ`MVP未採用`とし、専門確認完了まで利用しない。
- 移動式取締り・警察位置のリアルタイム音声通知は`MVP禁止`。
- 取得失敗・提供停止は、走行中には既存画面内の受動的な状態表示だけにする。

### JARTIC

- 一般公開ウェブページの無断第三者表示、公衆送信、転載、改変、類似サービス流用を前提にしない。
- ウェブページのスクレイピング再表示を禁止。
- オープンデータ・契約データは個別条件を確認する。

### オービス表示

- 一般的な安全運転注意は`確定要件`として許容。
- 地域・路線単位の粗い注意は`条件付き許容候補`。
- 正確座標の判断区分は`要専門確認`、MVP扱いは`未採用`。
- 移動式リアルタイム情報、ユーザー投稿型正確地点、回避ルートは`MVP禁止`。

### 地域差

- 警察庁資料から、地域の事故実態等に応じて地域重点を設定できることを確認。
- 本レビューで確認した東京・千葉・神奈川では、都県・警察署等の単位で速度管理・取締り指針を策定または公表している事例がある。
- 上記事例だけから、全都道府県・全警察署で同じ単位・形式により策定されると断定しない。
- 公表重点路線だけで取締り範囲を断定しない。

### 提供停止・縮退

- 規約変更、契約停止、権利不明、期限切れ、完全性懸念、安全判断不能時は必ず`提供停止`。
- 更新時刻不明で取得失敗・キャッシュ再表示ではない場合は原則`提供停止`。
- 更新時刻不明の非キャッシュ情報は、通常の制限表示条件が事前定義され、権利・上流由来・検証状態を追跡でき、競合がなく、安全な表示可否を判断できる場合のみ`制限表示`候補。
- 取得失敗キャッシュは、通常の制限表示条件に加えてキャッシュ専用条件を全て満たす場合のみ`制限表示`候補。
- 提供元更新時刻を取得できないキャッシュは`提供停止`。

### 訂正・通報

- 誤情報、古い情報、権利侵害、危険な表現を通報できる導線を用意する。
- 事実確認前に正誤を断定しない。
- 事故・閉鎖・オービス情報等で安全影響が高い通報を受けた場合、事実確認完了まで対象情報を必ず一時停止する。
- 通報者の位置、時刻、識別子を必要以上に公開しない。

## Technical Decisions

- 本レビューを法的助言・適法性の最終判断として扱わない。
- 判断区分を`確定要件`、`条件付き許容候補`、`MVP禁止`、`要専門確認`のいずれか1つに統一する。
- MVP扱いは判断区分とは別に管理する。
- 判断不能時はNo-Goとする。
- 正確地点接近音声は`要専門確認`かつ`MVP未採用`とする。
- 走行中の視覚・タップ操作を誘発する通知と、移動式取締り・警察位置のリアルタイム通知は`MVP禁止`とする。
- データ提供元採用前に再配布、加工、キャッシュ、帰属、停止条件を確認する。
- Next.js / Expo / DB / API / Auth / Infraを確定しない。
