## Issue #113で確定した画面表示境界

### 独立状態軸

次を独立して保持する。

1. 表示可否
2. 鮮度状態
3. 検証状態
4. 権利状態

利用者向け状態は4軸から導出し、`STOPPED` > `LIMITED` > `DISPLAYABLE`を適用する。

検証未完了・競合・検証失敗、権利失効、期限切れ、契約・規約判断不能、安全判断不能では情報本体を非表示にする。

### 固定必須表示

情報本体表示中は走行状態にかかわらず、情報源、参考情報、対象年月、提供元更新時点、鮮度・検証状態、制限・キャッシュ表示、情報限界、安全注意、JARTIC出典・RouteGarage加工表示を固定表示する。

維持できない画面では情報本体を非表示にする。

### キャッシュ再表示

旧版・キャッシュ表示は、保存・再表示許可、提供元更新時点、承認済み有効期限、撤回・完全性、由来・検証追跡、固定警告、承認記録の7条件をすべて満たす場合だけ制限表示候補とする。

1条件でも不足する場合は`STOPPED`。

### 共有・外部キャプチャ

- アプリ内共有前に生活拠点ぼかしとプレビューを必須とする。
- ブラウザ印刷では印刷専用表示・印刷CSSで正確位置・履歴を除去する。
- OS標準スクリーンショット・画面収録をアプリ内共有処理だけで防げると仮定しない。
- 正確位置・履歴表示には通常表示マスク、または検証済みキャプチャ保護と安全なフォールバックを必須とする。
- Webで安全要件を満たさない場合、正確位置・履歴とJARTICレイヤーの同時表示はNo-Go。

## Issue #115の現在方針

### データ分類

- 取得原本
- 説明書・フォーマット定義
- 正規化・加工後データ
- 表示用データ
- 過去スナップショット・履歴
- 一時ファイル・キャッシュ
- 検索インデックス・配信キャッシュ
- バックアップ・レプリカ
- 品質・権利・公開判定記録
- 監査メタデータ
- 削除墓標・削除完了証跡

公開Repositoryへのデータ本体保存とGoogle Maps Datasets等へのアップロードはNo-Goを維持する。

### 系譜

- 取得単位を`lineage_root_id`で識別する。
- 派生物を`artifact_id`で識別する。
- 原本ハッシュ、派生物ハッシュ、変換版、権利台帳`record_id`を関連付ける。
- 系譜を追跡できないデータは表示・履歴・共有・エクスポートNo-Go。

### 保持判断

- 保存目的、保存・加工・履歴・再表示許可、保持期限、再確認期限、承認者を保持開始前に記録する。
- 具体的な保持期間はprovider・契約・権利・技術構成の確定後に決定する。
- 期限値・根拠・承認者のいずれかがない保存はNo-Go。
- 監査目的だけを理由にデータ本体を無期限保存しない。

### 削除原則

- 表示停止を物理削除より先に実施する。
- 原本削除を正規化・加工後・表示用・履歴・キャッシュ・インデックス・バックアップ・外部保存先へ伝播する。
- 論理削除だけで完了扱いにしない。
- 部分失敗は未完了として再試行・エスカレーションする。
- 削除処理失敗を理由に対象データを再表示しない。

### バックアップ・復旧

- バックアップ最大残存期間を保持開始前に定義する。
- 削除期限を満たせないバックアップ方式はNo-Go。
- 復旧時は削除墓標・停止台帳・権利台帳の最新状態を先に適用する。
- 削除済み・失効・隔離中データを再公開しない。

### 監査メタデータ・削除墓標

- データ本体と監査メタデータを別ポリシーで管理する。
- 原本内容、正確位置、走行履歴、秘密情報、非公開回答本文を監査メタデータへ含めない。
- 削除墓標は再混入防止と完了説明に限定する。
- 墓標へデータ内容を保存しない。
- 監査メタデータ・墓標も保持期限を持ち、無期限保存しない。

### 法的保全

- 法務承認、対象範囲、目的、期限、アクセス制御、削除計画を必須とする。
- `LEGAL_HOLD`は公開・加工・再利用を許可しない。
- 保全と削除義務が競合する場合は判断完了までNo-Go。
