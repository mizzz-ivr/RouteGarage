# 愛車メンテナンス履歴 画面設計delta（Issue #138）

## 1. 目的

`docs/screen-design/screen-list.md` の既存ガレージ画面を壊さず、Issue #138で追加する整備・給油・走行距離履歴の画面責務をレビュー用deltaとして定義する。

本資料は要件レビュー用であり、UI実装・コンポーネント設計・API設計を確定しない。

## 2. 既存画面への変更候補

### SCR-05 ホーム（ダッシュボード）

追加候補:

- 次回メンテナンス目安が設定済みの場合の概要カード
- 「整備履歴を記録」への導線

制約:

- 走行中操作を促す通知文言にしない。
- `危険`、`走行不可`等の安全診断表現を使わない。
- ユーザー設定値に基づく目安であることを明示する。

### SCR-16 ガレージ管理

追加候補:

- 車両ごとの「メンテナンス履歴」導線
- 最新の有効走行距離候補
- 次回目安概要
- 車両アーカイブ候補

表示禁止:

- 他ユーザーの整備費用
- 他ユーザーの給油履歴
- 公開車両プロフィール経由の非公開メンテナンス情報

## 3. 新規画面候補

既存Issue #132の画面deltaと採番競合しない前提で、以下を候補とする。正本統合時に最新採番を再確認する。

### SCR-31 愛車メンテナンス履歴一覧

#### 利用者

対象車両の所有者。

#### 目的

選択車両の整備・給油履歴を時系列で確認し、記録追加・詳細確認・集計へ進む。

#### 主な表示

- 車両名
- 記録種別
- 実施日/給油日
- カテゴリ
- 走行距離
- 費用入力有無/費用
- 満タンフラグ（給油のみ）
- 有効な場合の区間燃費
- 次回目安概要
- 距離整合性警告

#### 主な操作

- 整備記録を追加
- 給油記録を追加
- 種別絞り込み
- 期間絞り込み
- 並び替え
- 記録詳細へ
- 集計表示へ

#### 安全/プライバシー

- 停車中または走行後の利用を明示する。
- 本人限定画面とする。
- 位置情報権限を要求しない。

### SCR-32 整備記録作成/編集

#### 利用者

対象車両の所有者。

#### 必須入力

- 実施日
- 整備カテゴリ
- 作業内容

#### 任意入力

- 走行距離
- 店舗名/作業者メモ
- 費用
- 個人メモ
- 次回目安日
- 次回目安走行距離

#### 主な表示

- 対象車両
- 入力値説明
- 距離逆転時の確認
- 次回目安は安全診断ではない旨
- カスタム記録に対する既存禁止方針

#### 主な操作

- 保存
- 編集保存
- 削除
- キャンセル

#### エラー候補

- 必須不足
- 費用負数
- 走行距離負数
- 不正日付
- 距離逆転
- 非所有車両
- 競合更新

### SCR-33 給油記録作成/編集

#### 利用者

対象車両の所有者。

#### 必須入力

- 給油日
- 走行距離
- 給油量
- 満タンフラグ

#### 任意入力

- 合計金額
- 単価
- 個人メモ

#### 主な表示

- 対象車両
- 前回の有効走行距離候補
- 距離逆転警告
- 満タンフラグ説明
- 燃費算出可否の説明

#### 主な操作

- 保存
- 編集保存
- 削除
- キャンセル

#### エラー候補

- 給油量0/負数
- 費用負数
- 単価負数
- 走行距離負数
- 距離逆転
- 不正日付
- 非所有車両
- 競合更新

### SCR-34 メンテナンス履歴詳細/集計

#### 利用者

対象車両の所有者。

#### 目的

個別記録または期間集計を確認し、派生値の根拠と算出不能理由を理解する。

#### 主な表示

- 整備詳細
- 給油詳細
- 期間費用候補
- 有効な区間燃費候補
- 燃費算出不能理由
- 次回目安
- 訂正/メーター交換に関する警告

#### 主な操作

- 編集
- 削除
- 一覧へ戻る
- 対象期間変更

#### 制約

- 算出不能を0km/Lとして表示しない。
- 欠損費用を0円として勝手に補完しない。
- 安全診断/車検適合保証を表示しない。

## 4. 画面遷移候補

```text
SCR-05 Home
  -> SCR-16 Garage
      -> SCR-31 Maintenance History
          -> SCR-32 Maintenance Create/Edit
          -> SCR-33 Fuel Create/Edit
          -> SCR-34 Detail/Summary
```

公開車両プロフィールやストーリー参照からSCR-31〜34へ遷移させない。

## 5. 状態別UI

### 正常

- 履歴あり
- 履歴なし
- 次回目安あり/なし
- 燃費算出可能/不能

### 距離不整合

距離逆転や未解決訂正がある場合:

- 警告を表示する。
- 燃費・距離目安を断定表示しない。
- 修正/理由確認へ誘導する。

### 車両アーカイブ候補

- 過去履歴閲覧は可能候補。
- 新規追加は停止候補。
- 完全削除は別確認を要求する。

最終仕様は後続設計で確定する。

## 6. Accessibility観点

- 色だけで期限超過/距離超過を表現しない。
- 数値・単位を読み上げ可能なテキストとして提供する。
- エラー項目とエラー理由を関連付ける。
- キーボード操作で記録作成・キャンセルまで到達できる設計へ引き継ぐ。
- 入力エラー時に既入力内容を不必要に破棄しない。

## 7. Responsive観点

Web MVPではスマートフォン幅も考慮するが、運転中利用は想定しない。

- 履歴一覧は小画面で横スクロール必須の巨大表にしない。
- 主要入力はラベルと値を縦方向に確認できる候補とする。
- 費用/距離/給油量の単位を入力欄から離しすぎない。

## 8. 対象外

- 車両整備画像アップロードUI
- レシートOCR
- OBD接続UI
- GPS取得UI
- 店舗検索/地図
- 整備予約/決済
- AI診断UI
- 公開/共有設定UI

## 9. 正本統合ルール

Issue #138の人間レビュー承認前に既存 `screen-list.md` / `screen-flow.md` を書き換えない。

承認後に:

1. 他の画面deltaを含む最新採番を確認する。
2. SCR-31〜34候補に競合があれば採番し直す。
3. SCR-16拡張内容を統合する。
4. 本人限定遷移と公開画面からの非到達をscreen-flowへ統合する。
5. 安全/プライバシー制約を削らない。
