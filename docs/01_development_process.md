# 01 Development Process

## ウォーターフォール開発の流れ
1. 要件定義
2. 基本設計
3. 詳細設計
4. 実装
5. テスト
6. リリース判定

## 各フェーズの成果物
- 要件定義: requirement Issue、要件ドキュメント
- 基本設計: design_task Issue、画面/データ/制約方針
- 詳細設計: 実装単位仕様、テスト観点
- 実装: feature_request Issueに紐づくPR
- テスト: テスト結果記録、残課題一覧
- リリース判定: リスク評価、Go/No-Go判断記録

## 完了条件
- フェーズ成果物がレビュー承認済み
- 次フェーズ開始に必要な前提が明文化済み
- 未確定事項が「保留」として管理されている

## レビュー方針
- 要件レビュー: PM/テックリード中心
- 設計レビュー: テックリード/アーキテクト中心
- 実装レビュー: コード品質 + 要件適合性
- テストレビュー: 完了条件の網羅性確認

## Issue化のタイミング
- 新規要求発生時: requirement Issue
- 設計が必要な単位: design_task Issue
- 実装着手可能時: feature_request Issue
- スコープ逸脱が発生した時: 別Issueを新規作成
