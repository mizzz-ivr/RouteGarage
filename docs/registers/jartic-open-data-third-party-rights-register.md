# JARTICオープンデータ 第三者権利台帳・公開判定手順（Issue #111）

- ドキュメント種別: 要件定義〜基本設計前フェーズの権利・公開判定台帳
- 対象Issue: https://github.com/mizzz-ivr/RouteGarage/issues/111
- 関連Issue: Issue #109
- 関連PR: PR #110
- 確認日: 2026-07-28
- AI利用: ChatGPT支援、人間レビュー必須
- 位置付け: 法的助言、権利確認完了、データ採用、実装設計ではない

## 1. 目的

JARTICオープンデータをRouteGarageで保存、加工、公衆送信、Google Map上へ表示、履歴公開する前に、第三者権利、上流由来、利用条件、表示義務、保存・加工可否を確認し、公開Go / No-Goを再現可能に判定する。

本台帳は、データセット名だけで一括承認するためのものではない。都道府県、原本ファイル、項目・地物、上流提供者、対象年月、版ごとに状態を追跡する。

## 2. 公式資料から確認した前提

### 2.1 JARTICオープンデータページ

- URL: https://www.jartic.or.jp/service/opendata/
- 提供分類:
  1. 交通規制情報
  2. 断面交通量情報
  3. 交通量データ（国土交通省）
  4. 交差点制御情報
- 各情報は原則毎月月初に更新される。
- 更新前の情報は提供元ページから取得できなくなる。
- 作業状況により更新が遅れる場合がある。

### 2.2 JARTICオープンデータ利用規約

- URL: https://www.jartic.or.jp/d/opendata/riyou_kiyaku.pdf
- 複製、公衆送信、翻訳・変形等の翻案、商用利用が可能とされている。
- 出典表示が必要である。
- 編集・加工時は加工した事実の表示が必要である。
- 加工後データをJARTIC、国、府省等が作成したように表示してはならない。
- 第三者が権利を有する場合がある。
- 権利処理済みであることが明示されていない第三者権利は、利用者の責任で確認・許諾取得が必要である。
- 第三者権利部分が明確に特定されていない場合もある。
- データは予告なく変更、移転、削除される場合がある。
- 利用規約は事前告知なく変更される場合がある。
- CC BY 4.0と互換性がある。

## 3. 基本原則

1. `オープンデータ`という名称だけで権利確認済みと判断しない。
2. `商用利用可能`という記載だけで第三者権利処理済みと判断しない。
3. データセット全体を一括で`確認済み`にしない。
4. 確認単位を、必要に応じて都道府県、ファイル、項目、地物まで分割する。
5. 証跡がない確認結果は`確認済み`にしない。
6. 口頭回答のみ、出典不明、適用版不明の回答はGo判定に使用しない。
7. `最新公開版`は、JARTICが現在公開している版を意味するだけであり、現在月、現在有効、リアルタイムを意味しない。
8. 対象年月、作成基準日、JARTIC公開更新日、RouteGarage取得日を独立して管理する。
9. 権利状態と鮮度状態を混同しない。
10. 判断不能時はNo-Goとする。

## 4. 管理単位

台帳レコードは、最低限次の組合せを一意に識別する。

- データセット種別
- 対象年月または作成基準日
- 都道府県・地域
- 原本ファイル名
- 原本ファイルハッシュ
- 説明書・フォーマット版
- 項目・カラム・地物の範囲
- 上流提供者・権利者候補

### 4.1 分割が必要な条件

次のいずれかに該当する場合、ファイルまたは項目単位へ分割する。

- 上流提供者が異なる
- 権利者表示が異なる
- 権利処理済みの明示範囲が限定されている
- 一部項目だけ第三者権利の可能性がある
- 一部都道府県だけ説明書・提供条件・フォーマットが異なる
- 一部地物だけ公開・加工・保存条件が異なる
- 同一ファイル内で公開可能部分と非公開部分が混在する
- 同一対象年月でファイル差替えが発生した

## 6. 状態

| 状態 | 意味 | 公開可否 |
| --- | --- | --- |
| 未着手 | 調査していない | No-Go |
| 調査中 | 資料・権利範囲を確認中 | No-Go |
| 確認済み | 必要証跡と承認が揃っている | 条件を満たせばGo候補 |
| 条件付き | 期限・表示・範囲等の条件がある | 条件充足時のみGo候補 |
| 非許可 | 利用不可または必要許諾を得ていない | No-Go |
| 失効・再確認必要 | 規約、ファイル、説明書、許諾等が変わった | No-Go |

### 6.1 `確認済み`の禁止条件

次のいずれかがある場合、`確認済み`にしない。

- 原本ハッシュがない
- 説明書・フォーマット版が不明
- 適用利用規約と確認日がない
- 上流提供者が不明
- 第三者権利の可能性が`不明`
- 権利処理済みの明示範囲が不明
- 必要な許諾証跡がない
- 公開・加工・保存のいずれかが未確認
- 必須出典・加工表示が確定していない
- 人間・法務・運用・安全の承認が不足している

## 7. 公開判定

### 7.1 公開Go候補

次をすべて満たす場合のみGo候補とする。

1. 管理単位が明確である
2. 原本、対象年月、地域、版、ハッシュを追跡できる
3. 上流由来と第三者権利者候補を追跡できる
4. 権利処理済み範囲または追加許諾を証跡で確認できる
5. 保存・加工・公衆送信・地図表示の可否を個別に確認した
6. 必須出典、加工表示、追加帰属を表示できる
7. 最新公開版を現在情報として扱わない
8. 旧版・履歴を現在情報と分離できる
9. 誤情報・権利問題・規約変更時に停止できる
10. 削除・非公開要求へ対応できる
11. 法務、運用、安全、プロジェクト責任者が承認した

### 7.2 条件付きGo

条件付きGoでは次を必ず記録する。

- 適用対象のファイル・項目・地域
- 許可される用途
- 禁止用途
- 必須表示
- 保存期限
- 再確認期限
- 失効条件
- 停止方法

条件を機械的または運用上強制できない場合はNo-Goとする。

### 7.3 No-Go

次のいずれかに該当する場合はNo-Goとする。

- 状態が未着手、調査中、非許可、失効・再確認必要
- 第三者権利の可能性が不明
- 必要許諾がない
- 原本・版・ハッシュ・証跡を追跡できない
- 出典・加工表示を満たせない
- 公開範囲を限定できない
- 権利未確認項目を除外できない
- 誤情報・権利侵害時に停止できない
- 削除要求へ対応できない
- 最新公開版を現在情報として誤認させる
- 法務・運用・安全・プロジェクト承認がない

## 8. 部分公開

権利未確認部分を含むファイルは原則No-Goとする。

部分公開を行う場合、次をすべて満たす。

- 公開部分と非公開部分を項目・地物単位で確実に分離できる
- 分離処理の仕様・版・テスト結果を記録できる
- 非公開部分が出力、ログ、キャッシュ、バックアップに残らない
- 加工によって原本の意味を変更しない
- 公開部分だけの権利・出典・加工表示を確認した
- 法務・安全レビューが部分公開を承認した

欠損補完、権利状態の推定、上流由来の推定で公開範囲を広げない。

## 9. 差替え・変更時の再確認

次のイベントで対象レコードを`失効・再確認必要`へ変更する。

- 同一対象年月のファイルハッシュが変わった
- 原本ファイル名・構成が変わった
- 説明書・フォーマット版が変わった
- 利用規約本文または規約PDFハッシュが変わった
- 出典・上流提供者の記載が変わった
- 第三者権利に関する新しい情報が出た
- 提供元が訂正・削除・移転した
- 許諾期限・再確認期限を超えた
- 誤情報・権利侵害通報を受けた

再確認完了まで公開を停止する。

## 10. 最新公開版・鮮度補足

`最新公開版`は次を意味しない。

- 現在月のデータ
- 現在有効な規制
- 現在の渋滞・交通量
- リアルタイム情報
- 緊急・一時規制情報

表示と台帳では次を独立して保持する。

- 対象年月・作成基準日
- JARTIC公開更新日
- RouteGarage取得日
- RouteGarage検証日
- 権利確認日

表示上のラベルは`JARTIC公開中の最新月次版`等とし、`最新交通情報`とは表現しない。

## 11. 通報・一時停止・再開

### 11.1 即時一時停止

次の場合、対象ファイル・項目・レイヤーを即時停止する。

- 権利侵害の可能性が高い通報
- 誤情報による安全影響の可能性
- 出典・加工表示の欠落
- 上流提供者・権利者からの停止要請
- 規約変更後の利用可否不明
- 原本と公開データの対応喪失
- ハッシュ・真正性の不一致

### 11.2 調査記録

- 通報日時
- 通報経路
- 対象record_id
- 影響範囲
- 一時停止日時・実施者
- 証拠・資料参照ID
- 法務・運用判断
- 訂正・削除内容
- 再発防止策

### 11.3 再開条件

- 原因と影響範囲を特定した
- 権利・安全上の問題を解消した
- 出典・加工表示を修正した
- 原本・変換後・公開データの対応を再検証した
- 法務、運用、安全、プロジェクト責任者が再開を承認した

## 12. 公開Repositoryと非公開証跡

### 12.1 公開Repositoryへ記録可能

- 台帳様式
- 公開資料のURL・確認日
- 公開可能な判定要約
- 証跡参照ID
- 状態・停止理由の公開可能な要約
- 非機密の出典・加工表示文言

### 12.2 公開Repositoryへ保存しない

- 非公開契約書
- 第三者からの非公開回答
- 個人名・個人メール・電話番号
- 未公開の許諾書・見積
- アクセス制御が必要な証拠ファイル
- APIキー・秘密鍵・トークン
- 利用者の位置情報・走行履歴

非公開証跡はアクセス制御された保管先へ保存し、Repositoryには参照IDのみを記録する。

## 14. テスト観点

### 正常系

- 証跡と承認が揃ったレコードだけをGo候補にできる
- 条件付きGoの期限・範囲・表示義務を確認できる
- 原本ハッシュから公開データまでの判断を追跡できる

### 異常系

- 証跡欠落時に`確認済み`へ変更できない
- 第三者権利不明時に公開できない
- 規約・ファイル変更時に自動的または運用上`失効`へ変更できる
- 通報時に対象レイヤーを停止できる

### 境界値

- 同じ対象年月でファイルだけ差し替わった場合
- 一部項目だけ権利処理済みの場合
- 許諾期限当日・再確認期限超過
- 地域ごとに上流提供者が異なる場合

### 既存影響

- JARTIC月次データを現在情報へ昇格させない
- C-01 Google Routesの保存境界と混同しない
- JARTIC Jシステム / VICSの契約データと混同しない
- 非公開証跡を公開Repositoryへ保存しない

## 15. ADR

追加しない。

JARTICデータセット、対象ファイル、保存方式、表示方式を採用決定していないため、ADRは実データ候補選定または基本設計時に作成する。
