- ドキュメント種別: 要件定義フェーズの取得前プレフライト
- 対象Issue: Issue #126
- 関連Issue: Issue #111 / #113 / #115 / #121 / #124
- 確認日: 2026-08-05
- 再確認期限: 2026-09-04
- AI利用: ChatGPT支援、人間レビュー必須
- 現在判定: `調査中 / No-Go`
- 位置付け: 法的助言、権利確認完了、交通規制の法的解釈、データ採用、実装設計ではない

## 1. 目的

JARTICが公開する交通規制情報について、実データ取得・保存・表示・ルート判定へ進む前に、公開資料で確認できる上流由来、権利候補、意味・鮮度・安全上の境界を整理する。

JARTIC公式の「交通規制情報（拡張版標準フォーマット）説明書 Ver: k_2.1」は公開済みであり、本Issueで表紙、改訂履歴、導入部、ファイル仕様、構成・コード表・位置表現の一部を予備レビューした。ただし、全96ページの項目別定義、別記、コード表、第三者権利、運用上の意味を通読・承認しておらず、対象地域・対象月の実ファイルも取得していない。

このため、公開済み説明書を「存在不明」とは扱わない一方、項目名・コード値・必須・任意・値域・欠損表現・版互換性をRouteGarageの確定仕様にはしない。

## 2. 結論

交通規制情報全体を`調査中 / No-Go`とする。

次の利用は、公式説明書の全体レビュー、対象地域・対象月の実ファイル、原本ハッシュ、項目別権利、データ品質、および**法務・運用・安全・セキュリティ・プライバシー・交通情報／ナビゲーション領域・プロジェクト責任者**のレビューと承認が揃うまで禁止する。

- 原本・正規化データの保存
- 参考情報としての一般公開
- 地図・ルート上への規制表示
- ルート探索・通行可否判定
- 自動運転・安全運転支援への入力
- 履歴保存・履歴公開
- CSV / GeoJSON等のエクスポート
- Google Maps Datasets等へのアップロード

## 3. 公開資料から確認した事実

### 3.1 JARTIC公開ページ

- 交通規制情報は、各都道府県警察が保有する交通規制データベースに入力された情報を、交通規制に係る拡張版標準フォーマットへ変換した情報である。
- 都道府県単位のZIPファイルとして提供される。
- 作成基準日とフォーマット版は「作成基準日等データ」で確認するよう案内される。
- 2026-08-05確認時点の公開説明は`拡張版_K_2.1`である。
- 原則毎月月初に更新され、更新前の情報は取得できなくなる。
- 更新作業が遅れる場合がある。

### 3.2 公式説明書 Ver: k_2.1

公式PDF:

- https://www.jartic.or.jp/d/opendata/typeD_kisei_73_k_2.1.pdf

予備レビューで確認した事項:

- 文書名: 交通規制情報（拡張版標準フォーマット）説明書
- 文書版: `k_2.1`
- `k_2.0`: 2024-04-22 初版
- `k_2.1`: 2025-01-20 ユニークキー付与規則および対象コードの改訂
- PDFページ数: 96ページ
- 従来形式の103規制種別・224項目を、拡張版では最大73規制種別・170項目へ集約すると説明される。
- CSVはShift-JIS、CR+LF、半角カンマ区切り、ヘッダーあり、値をダブルクォーテーションで囲む仕様である。
- 都道府県警察ごとに原則1ファイルで、ファイル名に対象年月とフォーマット版を含む。
- 点規制・線規制・面規制、規制方向、対象、曜日等のコード表と座標登録方法が説明される。
- データ更新区分コードにより差分抽出へ対応すると説明される。
- データ作成後の変更、DB入力時期との差、入力漏れ・誤り等により、記録内容が実際の交通規制とすべて一致するとは限らず、未記録の規制もあり得ると明記される。
- 実際の運転・利用時は道路標識および道路標示に従うよう明記される。

### 3.3 拡張版標準フォーマットの背景

- 警察庁がSIP第2期の調査研究で取りまとめたフォーマットである。
- 自動運転システムや安全運転支援等で交通規制情報を活用する目的がある。
- 従来フォーマットの構造上の課題解決とデータ精度向上を目的とする。
- 規制の方向に関する情報等が追加されたと説明される。

### 3.4 JARTIC利用規約

- 数値データ、簡単な表・グラフ等は自由利用可能と説明される。
- 出典表示が必要である。
- 編集・加工時は加工した事実の表示が必要である。
- 加工後の情報をJARTIC、国、府省等が作成したように表示してはならない。
- 第三者が著作権その他の権利を有する場合がある。
- 権利処理済みと明示されていない第三者権利は、利用者責任で確認・許諾取得する必要がある。
- 第三者権利部分が明確に特定されていない場合がある。
- データは予告なく変更・移転・削除される場合がある。

### 3.5 交通規制・交通情報提供の安全上の位置付け

- 警察庁は交通規制を、道路における危険防止、交通の安全と円滑、交通公害防止のために行うものと説明する。
- 交通情報提供事業者には、正確かつ適切な交通情報を提供し、交通の安全と円滑に資するよう配慮することが求められる。

## 7. 独立して管理する状態

一つの`valid`フラグへ統合しない。

- `rights_status`: 権利確認状態

- `freshness_status`: 作成基準日・公開日・再確認期限
- `semantic_status`: コード・項目意味の確認状態
- `position_status`: 点・線・面・座標の確認状態
- `direction_status`: 規制方向・進行方向の確認状態
- `subject_status`: 対象車両・対象交通・例外の確認状態
- `temporal_status`: 開始・終了・曜日・時間帯・例外期間の確認状態
- `conflict_status`: 重複・矛盾・廃止・更新の確認状態
- `publication_status`: 表示可否
- `routing_status`: ルート探索・通行可否判定への利用可否
- `stop_status`: 一時停止・失効状態

`stop_status = STOPPED`を最優先する。

## 9. 安全表示要件候補

将来表示を再評価する場合の最低条件であり、現時点の表示許可ではない。

- `現在の交通規制`、`リアルタイム`、`通行可能`と断定しない。
- 対象月、作成基準日、JARTIC公開日、RouteGarage検証日を区別する。
- 情報本体と同じ画面範囲に出典・加工表示・鮮度注意を表示する。
- 現地の道路標識・道路標示、警察官等の指示を優先する旨を表示する。
- 位置、方向、対象車両、期間、例外のいずれかが不明なら規制情報本体を表示しない。
- 欠損・矛盾・期限超過時は`STOPPED`へ倒せる設計を検討する。
- 走行中に詳細確認・編集・通報操作を要求しない。
- ルート探索へ利用する場合は、表示用途と別の承認ゲートを持つ。

## 10. フェイルセーフ

### 10.1 不明値

- 不明値を通常値へ補完しない。
- 方向不明を両方向へ拡張しない。
- 対象車両不明を全車両へ拡張しない。
- 終了日時不明を無期限へ拡張しない。
- 位置不明を近隣道路へスナップしない。

### 10.2 矛盾

次の場合は対象レコードまたはレイヤーを停止する。

- 同一規制に複数の矛盾する規制種別がある
- 始終点・方向が矛盾する
- 期間が逆転または重複する
- 更新版と旧版の対応を追跡できない
- 現地・公式情報との重大な不一致通報がある

### 10.3 期限超過

- 再確認期限超過時は`失効・再確認必要 / No-Go`とする。
- 新規取得、再生成、公開、ルート利用を停止する。

- 更新・廃止・訂正・重複の扱い
- 項目別の第三者権利・原典
- 表示、ルート探索、公衆送信、再配布の条件
- 交通情報提供指針との適用関係

- プロダクト
- 法務

- 安全
- セキュリティ
- プライバシー
- 交通情報・ナビゲーション領域

## 13. Go候補の最低条件

1. 対象都道府県・対象月・利用目的を人間が承認する。
2. 公式説明書全体と作成基準日等データを確認し、版・ハッシュを登録する。
3. 取得前の非公開保管、保持、削除、アクセス権を承認する。
4. 実ファイルの原本ハッシュと系譜を登録する。
5. 項目・コード・欠損・不明値・版互換性を確認する。
6. 項目別の上流由来と第三者権利を確認する。
7. 位置・方向・対象・期間・例外の完全性と矛盾検査を定義する。
8. 月次スナップショットを現在情報と分離する。
9. 表示用途、ルート用途、安全運転支援用途を別々に承認する。
10. プロダクト、法務、運用、安全、セキュリティ、プライバシー、交通情報・ナビゲーション領域、プロジェクト責任者が承認する。

一つでも不明ならNo-Goを維持する。

## 14. テスト観点

### 14.1 正常系

- 項目群から上流主体、権利、意味、安全ゲートを追跡できる。
- 位置・方向・対象・期間・例外が揃った場合だけ次段階の評価対象にできる。
- 版、説明書改訂日、作成基準日、公開日、検証日を独立して管理できる。
- 公開済み説明書と、未レビュー・未取得の証跡を区別できる。

### 14.2 異常系

- 利用規約だけで全項目をGoにしない。
- 説明書が公開済みであることだけで実データ利用をGoにしない。
- 月次データを現在有効な規制として案内しない。
- 欠損値を推定補完してルート探索に使わない。
- 現地標識よりアプリ情報を優先する案内をしない。
- 再確認期限超過後に公開・再生成しない。

### 14.3 境界値

- 説明書公開済み・未レビュー・レビュー済みの状態遷移。
- 作成基準日と公開日が異なる。
- 開始・終了日時の直前、同時刻、直後。
- 曜日、時間帯、祝日、季節条件の境界。
- 点・線・面規制の境界。
- 片方向、両方向、不明の境界。
- 対象車両あり、例外車両あり、対象不明。
- 同一規制の重複、矛盾、廃止、更新。
- `k_2.1`から将来版への変更。
- 再確認期限2026-09-04当日と翌日。

### 14.4 回帰

- 出典・加工・鮮度・安全表示要件を弱めない。
- 表示停止を物理削除より先に行う。
- 原本から派生物・キャッシュ・バックアップ・外部保存先まで削除を伝播する。
- 正確位置・生活拠点・走行履歴の公開保護を弱めない。
- 実データ・非公開証跡を公開Repositoryへ保存しない。
