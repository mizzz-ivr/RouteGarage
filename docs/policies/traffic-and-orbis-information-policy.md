# 交通情報・オービス情報の正確性限界表示と法令・規約適合方針（Issue #89）

- ドキュメント種別: 要件定義〜基本設計前フェーズの方針文書（実装仕様・法的助言ではない）
- 対象Issue: Issue #89
- Issue URL: https://github.com/mizzz-dev/RouteGarage/issues/89
- 関連要件: `docs/requirements/mvp-requirements.md`（FR-ROAD-01〜03、FR-ORBIS-01〜03、NFR-SAFE-01〜02、NFR-OPS-02、NFR-AUD-02）
- 関連方針: `docs/policies/driving-safety-ui-policy.md`
- 関連リスク: `docs/risks/risks.md`（R-003、R-004）

## 1. 目的

交通情報・事故情報・PA閉鎖情報・オービス情報を扱う際の、情報品質、表示責任、走行安全、情報提供元規約、商用運用の判断基準を定義する。

本書は「表示できること」を先に決めるのではなく、誤情報、更新遅延、無断再配布、取締り回避を助長する表現、走行中の画面注視を防ぐための要件を固定する。

## 2. 適用範囲

- Web MVPにおける交通情報・事故情報・PA閉鎖情報の参考表示
- オービス情報または速度取締り関連情報として認識される表示
- 情報の更新時刻、鮮度、未検証、競合、停止状態の表示
- 情報提供元の利用規約・ライセンス・再配布条件の確認
- ユーザー投稿型情報を将来扱う場合の最低限ガードレール
- 問い合わせ、訂正、通報、障害、監査証跡の運用要件

以下は本書では確定しない。

- 採用する交通情報API、地図API、オービス情報提供元
- データ契約、料金、SLA
- 表示粒度、更新間隔、鮮度閾値の具体数値
- DB/API/Auth/Infra/Deployment/Monitoringの設計
- Next.js / Expoの実装方式
- 個別機能の適法性に関する最終判断

## 3. 公式資料から確認した前提

### 3.1 走行中の画面注視

警察庁は、車両が停止している場合を除き、運転中にスマートフォン等を通話に使用したり、画像表示用装置の画像を注視したりしないことを示している。また、使用が必要な場合は安全な場所に停車してから使用するよう案内している。

RouteGarageでは、交通情報・オービス情報の表示有無にかかわらず、走行中の注視や操作を前提にしない。

### 3.2 交通情報の完全性・更新遅延

JARTICの利用規約では、掲載コンテンツがネットワークやシステムのトラブル等により完全でない場合があることが示されている。オープンデータ案内でも、更新が遅れる場合や、更新前データを取得できなくなる場合が示されている。

RouteGarageは「公式情報であること」と「常に完全・最新であること」を同一視しない。

### 3.3 コンテンツ利用条件

JARTICのウェブサイト利用規約では、私的使用等の範囲を超えた第三者への表示、提供、公衆送信、転載、改変、類似サービスへの流用等が制限されている。オープンデータ等の個別提供物は、各提供条件を別途確認する必要がある。

RouteGarageは、公開ウェブページをスクレイピングして再配布できる前提を置かない。

## 4. 情報区分

表示する情報は、最低限以下の区分を保持する。

| 区分 | 定義 | 表示上の必須要素 |
| --- | --- | --- |
| 公式・契約情報 | 行政機関、道路管理者、契約したデータ提供元から取得 | 情報源、更新時刻、受信時刻、利用条件に基づく帰属表示 |
| オープンデータ | 明示された利用条件で再利用可能な公開データ | データ名称、提供者、基準日、ライセンスまたは利用条件 |
| ユーザー投稿 | 利用者が投稿・通報した情報 | 未検証表示、投稿時刻、通報導線、有効期限候補 |
| 派生・推定情報 | 複数情報からRouteGarageが計算・推定 | 推定である旨、算出基準の版、根拠情報の区分 |
| 不明 | 情報源や確認状態を特定できない | 原則非表示。管理画面等でも要確認状態として隔離 |

公式情報とユーザー投稿を、同じアイコン・色・ラベルで表示してはならない。

## 5. 鮮度・状態表示要件

### 5.1 必須表示

交通情報を表示する場合、ユーザーが以下を確認できること。

- 情報源または情報源区分
- 情報提供元の最終更新時刻（取得可能な場合）
- RouteGarageが受信した時刻
- 現在の状態（最新扱い、遅延、未検証、競合、提供停止）
- 情報欠落・更新遅延・実際の状況との差異があり得る旨
- 本情報のみを運転判断の唯一根拠にしない旨

### 5.2 状態区分

| 状態 | 判断 | UI方針 |
| --- | --- | --- |
| 最新扱い | 採用データ提供元の更新仕様とRouteGarageの鮮度基準内 | 通常表示。ただし参考情報表示は維持 |
| 遅延 | 鮮度基準を超過、または提供元が遅延を通知 | 遅延を明示し、強調度を下げる |
| 未検証 | ユーザー投稿等で裏付け未完了 | 未検証ラベルを固定し、公式情報と分離 |
| 競合 | 複数情報源で内容が一致しない | 一方を正しいと推測せず、競合状態を表示または非表示 |
| 提供停止 | 取得失敗、契約停止、規約変更、障害 | 情報を推測表示せず、停止案内へ切り替える |
| 期限切れ | 有効期限を超過 | 地図・一覧から除外し、必要な場合のみ履歴として保持 |

具体的な時間閾値は、データ提供元・情報種別・契約SLA確定後に基本設計Issueで決定する。

## 6. オービス情報の扱い

### 6.1 基本目的

オービス情報は、速度遵守・安全運転の注意喚起を目的とする。速度取締りの回避、警察活動の妨害、危険運転の継続を支援する目的では扱わない。

### 6.2 許容候補

法務・規約・情報提供元レビュー後に、以下を許容候補として検討する。

- 制限速度・安全運転を守る一般的な注意喚起
- 情報源、基準日、更新状態を伴う参考表示
- 「取締りの有無にかかわらず法定速度を守る」旨の固定表示
- 地域・路線単位等の粗い注意表示

### 6.3 禁止事項

MVPでは以下を実装しない。

- 「取締りを避ける」「ここだけ減速すればよい」等の回避を示唆する文言
- 取締り地点を避けるルート最適化
- 通過成功、回避回数、速度等を競わせるランキング・バッジ・ゲーム化
- 未確認のリアルタイム警察位置・移動式取締り情報の即時拡散
- 情報源・更新時刻を隠した断定表示
- 実際の制限速度を超える速度を推奨・許容する表示
- 提供元の許諾なく取得した位置情報や画像の転載

### 6.4 未確定事項

以下は法務・運用・ストア審査・データ提供元確認後に決定する。

- 正確な座標を表示するか、地域・路線単位に留めるか
- 固定式・移動式・ユーザー投稿情報の対象範囲
- 通知の有無、通知距離、通知頻度
- 地域別法令・ガイドラインへの対応
- App Store / Google Play等の審査観点（ネイティブアプリはMVP対象外）

## 7. 走行安全UI要件

`docs/policies/driving-safety-ui-policy.md` を優先して適用する。

- 走行中の入力、投稿、訂正、通報、フィルター変更を前提にしない
- 情報カードは短時間の注視を促す高密度表示にしない
- 更新要求、再読込、詳細確認は停車中利用を前提とする
- 走行中判定が未確定な場合は閲覧中心・制限側に倒す
- 警告を閉じないと情報が見られない反復ダイアログは避け、固定注意領域を用いる
- 音声案内・バックグラウンド通知は、本Issueでは採用しない

## 8. 情報提供元の採用前チェックリスト

データ提供元を採用する前に、以下をIssueまたはADRで記録する。

- 商用利用の可否
- アプリ・ウェブ画面での表示可否
- 第三者への再配布・公衆送信・キャッシュの可否
- データ加工・派生データ作成の可否
- 必須帰属表示、ロゴ、リンク、著作権表記
- 保存可能期間と削除義務
- 更新頻度、遅延、欠落、訂正通知の仕様
- 利用可能地域と地域別制限
- API停止・規約変更・契約終了時の対応
- ユーザー投稿との統合可否
- 問い合わせ・監査時に根拠を提示できるか
- 規約確認日、規約バージョン、確認者

確認が完了していない情報源は、実装候補として確定しない。

## 9. 縮退運用

### 9.1 取得失敗・遅延

- 前回データを「現在情報」として無条件に表示しない
- キャッシュ表示する場合は、取得時刻と期限切れ状態を明示する
- 有効性を判断できない場合は非表示または提供停止表示へ切り替える
- 他の情報源から推測して補完しない

### 9.2 規約変更・契約停止

- 対象データ表示を停止できる機能フラグまたは運用手順を後続設計で用意する
- 帰属表示・キャッシュ削除・データ削除義務を確認する
- 利用者向け告知と問い合わせテンプレートを準備する

### 9.3 誤情報・事故報告

- 訂正依頼・通報を受け付ける導線を用意する
- 安全影響が高い場合は対象情報を一時非表示にできること
- 事実確認前に正誤を断定しない
- 対応経緯、判断者、時刻、表示文言版を記録する

## 10. 商用運用・監査要件

最低限、以下を追跡可能とする。

- データ提供元、契約・利用条件、確認日、確認者
- 表示文言と注意文言のバージョン
- 情報取得時刻、受信時刻、表示状態
- 提供停止、期限切れ、競合、未検証への状態遷移
- 訂正依頼、通報、非表示化、復旧の判断履歴
- 規約変更・法務レビューによる仕様変更履歴

ログ項目、保持期間、保存方式、閲覧権限は基本設計Issueで確定する。

## 11. 推奨表示文言の要件

文言は画面詳細設計で確定するが、以下の意味を含める。

- 「参考情報であり、実際の道路状況と異なる場合があります」
- 「更新時刻と情報源を確認してください」
- 「安全な場所に停車してから操作してください」
- 「取締りの有無にかかわらず、法定速度と交通ルールを守ってください」

「必ず正しい」「リアルタイム保証」「この地点以外は安全」等の断定表現は禁止する。

## 12. 受け入れ条件

- FR-ROAD-01〜03、FR-ORBIS-01〜03との対応関係を説明できる
- 公式・契約情報、オープンデータ、ユーザー投稿、推定情報を区別している
- 更新時刻、鮮度、未検証、競合、停止、期限切れの状態を定義している
- オービス情報の安全運転目的と禁止事項が明記されている
- 走行中操作・画面注視を助長しない
- 情報提供元の利用条件確認を実装前ゲートとしている
- 縮退運用、訂正、問い合わせ、監査要件が定義されている
- 未確定事項が明記され、技術・データ提供元を確定していない

## 13. 後続Issueへの引き継ぎ

1. 法務・運用レビュー: オービス表示粒度、通知可否、地域差、利用規約整合
2. データ提供元調査: 候補ごとの商用利用・再配布・キャッシュ・帰属条件比較
3. 画面詳細設計: 状態ラベル、注意表示、停止表示、訂正・通報導線
4. 基本設計: 鮮度判定、状態遷移、機能フラグ、監査ログ
5. 運用設計: 規約変更監視、訂正対応、事故・苦情エスカレーション
