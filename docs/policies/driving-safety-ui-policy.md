# 走行安全UI/UX詳細方針（Issue #18）

- ドキュメント種別: 要件定義〜基本設計前フェーズの方針文書（実装仕様ではない）
- 対象Issue: Issue #18
- Issue URL: https://github.com/mizzz-dev/RouteGarage/issues/18
- 関連要件: `docs/requirements/mvp-requirements.md`（FR-MAP-03, FR-ROAD-03, FR-ORBIS-01〜03, NFR-SAFE-01〜02）
- 関連設計: `docs/screen-design/screen-list.md` / `docs/screen-design/screen-flow.md`
- 関連ポリシー: `docs/policies/location-and-drive-log-data-policy.md`

## 1. 目的
RouteGarageにおいて、走行中操作を助長しないためのUI/UX制約を定義し、後続の画面詳細設計・基本設計で一貫して適用できる判断基準を固定する。

## 2. 適用範囲
- Web MVPの全画面（SCR-01〜SCR-20）
- 特に高リスク操作（投稿、編集、公開設定変更、画像アップロード、コメント相当入力）
- 交通情報・オービス情報を表示する画面

> 注記: 走行中判定アルゴリズム、GPS処理、地図API連携、実装方式は未確定であり本書では決定しない。

## 3. 基本原則
1. **停止時利用原則**: 入力・投稿・編集・公開変更は停車中利用を前提とする。
2. **保守的制御原則**: 走行中か未確定な場合は「操作可能」とみなさず制限側に倒す。
3. **誤認防止原則**: 交通情報・オービス情報は運転判断の唯一根拠にしない表示を維持する。
4. **最小公開原則**: 公開系操作は非公開寄り初期値と確認ステップを必須化する。
5. **説明責任原則**: 制限理由、更新遅延、情報限界、問い合わせ導線を常に提示可能とする。

## 4. 走行中に禁止する操作

### 4.1 原則禁止（走行中は実行不可）
- 投稿の新規作成・編集・削除（スポット投稿、コミュニティ投稿）
- 画像アップロード・画像差し替え・画像削除
- 走行記録の新規作成・編集・削除
- 公開範囲変更（公開/非公開切替）
- 問い合わせ本文の新規入力・送信
- 長文入力、複数ステップ入力、確認ダイアログを伴う確定操作

### 4.2 保守的制限（未確定時も制限）
- 走行中判定が未確定・取得失敗・矛盾状態の場合、4.1の操作は同様に不可とする。
- 可否判定が復旧するまで、閲覧中心モード（Read Only）を維持する。

### 4.3 例外方針
- 緊急連絡や法令対応の例外操作は本Issueでは確定しない（要確認）。
- 例外が必要な場合でも、最小操作・最短導線・誤操作防止を前提に別Issueで定義する。

## 5. 停車中利用を前提とする導線方針

### 5.1 画面別の扱い
- 閲覧中心画面（例: SCR-06, SCR-07, SCR-12, SCR-15）は表示継続可。ただし注意表示を固定。
- 入力中心画面（例: SCR-09, SCR-11, SCR-16, SCR-19, SCR-17, SCR-18）は停車中前提の制約表示を先頭固定。

### 5.2 導線設計ルール
- 禁止操作を含むボタンは、走行中/未確定時に無効化し理由を表示する。
- 停車後の再開を想定し、下書き再開や入力保持の必要性を後続Issueで検討する（本書では仕様確定しない）。
- 走行再開時は入力系画面を自動的に閲覧中心状態へ遷移させる方針とする（詳細条件は未確定）。

## 6. 投稿・編集・画像・コメント相当操作の制限方針
- 投稿/編集/削除/公開切替は停車確認後にのみ確定可能。
- 画像アップロード前に、位置情報・人物・ナンバープレートの注意を毎回表示する。
- コメント機能はMVP対象外だが、将来のコメント相当入力も同制約を適用する。
- 走行中に入力途中となった内容は、意図しない公開を防ぐため自動公開しない。

## 7. 交通情報・オービス情報の表示方針（誤認防止）
- 「参考情報」であることを画面固定領域に表示する。
- 更新時刻、遅延・誤差の可能性、情報欠落可能性を明記する。
- 「本情報のみで運転判断しない」旨を明記する。
- オービス情報は安全運転啓発目的に限定し、違反回避を目的と誤認される表現を禁止する。
- 情報停止時は非表示または停止表示に切り替え、推測表示しない。

## 8. 走行中判定が未確定な場合の保守的UI方針
- 判定不可時は「安全のため操作を制限中」と表示する。
- 解除条件が不明な状態では解除を約束しない。
- 再判定を促す導線は提供するが、運転中操作を促す文言は使用しない。
- 未確定状態の継続時に問い合わせ導線を表示し、サポートへ接続する。

## 9. 商用運用を見据えた要件
- 利用規約・注意表示: 停止時利用原則、情報限界、免責範囲を整合させる。
- 問い合わせ対応: 「操作制限理由」「解除されないケース」の説明テンプレートを運用側で整備する。
- 監査ログ要件: 制限状態での操作試行、公開範囲変更、投稿確定、削除を追跡対象候補とする（実装詳細は未確定）。
- 事故・トラブル時説明責任: 表示文言バージョン、適用時刻、制限状態の記録を参照可能にする方針とする。

## 10. 未確定事項（断定しない）
- 走行中判定の具体入力データ、閾値、アルゴリズム
- 判定頻度、遅延許容値、誤判定時の救済フロー
- 下書き保存仕様、自動遷移の厳密条件
- 監査ログの保持期間・保管方式
- 法務レビュー後のオービス表示粒度

## 11. 後続Issueへの引き継ぎ
1. 画面詳細設計Issue: 画面ごとの文言、無効状態UI、固定注意領域の配置
2. 基本設計Issue: 制限状態管理、監査ログ項目、問い合わせ連携
3. 法務/規約Issue: 免責文言、オービス表示表現、利用規約整合
4. 運用Issue: サポートFAQ、事故時説明テンプレート、エスカレーション手順
