## Review Findings

CodexレビューでP1指摘を合計5件受領した。

1. 表示可否・鮮度・検証・権利状態を単一コードへ統合しないこと
2. 取得失敗時の旧版・キャッシュ再表示に既存ポリシーの全条件を課すこと
3. 提供元更新時点、情報限界、運転判断注意、停車操作注意を固定表示すること
4. 共有画像・印刷・エクスポートに自宅・職場周辺ぼかしと事前プレビューを必須化すること
5. 走行中も情報源・鮮度・検証を含む固定必須表示を維持し、維持できなければ情報本体を非表示にすること

## Fix 1: 独立状態軸

`docs/policies/traffic-and-orbis-information-policy.md`第5章との整合を取り、次を独立軸として定義した。

- 表示可否
- 鮮度状態
- 検証状態
- 権利状態

利用者向け状態は4軸を置き換える保存値ではなく、画面表示用の導出結果とした。

優先順位:

`STOPPED` > `LIMITED` > `DISPLAYABLE`

権利失効、期限切れ、競合、検証失敗、契約・規約判断不能、安全判断不能時は情報本体を非表示にする。

## Fix 2: 取得失敗時のキャッシュ条件

取得済み旧版・キャッシュの制限表示を、次の全条件充足時だけに限定した。

1. 規約・契約上の保存・再表示許可
2. 提供元更新時点を取得済み
3. 事前承認済みキャッシュ有効期限内
4. 契約停止、規約変更、撤回、無効化、改ざん・完全性懸念なし
5. 上流由来、調達経路、検証状態を追跡でき、競合なし
6. `現在取得失敗中`、`キャッシュ情報`、`提供元更新時点`を固定表示可能
7. 制限表示ルール、承認者、承認記録あり

1条件でも不足する場合は`STOPPED`とする。

## Fix 3: 固定安全注意

情報本体を表示する間、地図画面の固定領域で次を常時確認可能とした。

- 情報源・提供元
- 対象年月・作成基準日
- 提供元更新時点
- 鮮度状態・検証状態
- 制限表示・キャッシュ表示の旨
- 欠落・遅延・誤差・実際の状況との差異の可能性
- 本情報のみを運転判断の唯一の根拠にしない旨
- 詳細操作は安全な場所に停車してから行う旨

## Fix 4: 共有前の生活拠点ぼかし

`docs/policies/location-and-drive-log-data-policy.md`第6章へ合わせて、共有・スクリーンショット・印刷・エクスポート前に次を必須化した。

- 自宅・職場・走行開始地点・走行終了地点・反復訪問地点周辺への機械的ぼかし
- 現在位置マーカーだけでなく、道路形状、開始・終了地点、表示中心、履歴からの再推定リスク確認
- 共有前プレビューでぼかし結果、対象範囲、帰属、対象年月を確認
- ぼかし解除を公開初期値にしない
- ぼかし後も再推定リスクが残る旨を表示

ぼかしアルゴリズム・距離閾値が未確定の間、位置・走行履歴を含む共有出力はNo-Goとした。

## Fix 5: 走行中の固定必須表示

走行中・走行状態不明時も、情報本体を表示する場合は固定必須表示を省略しない。

必須項目:

- 情報源・提供元
- 対象年月・作成基準日
- 提供元更新時点
- 鮮度状態
- 検証状態
- 制限表示・キャッシュ表示
- 情報限界と安全注意

小画面・走行中UIで維持できない場合は、項目を省略せずJARTICレイヤー本体を非表示にする。
