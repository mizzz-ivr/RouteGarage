# 2026-05-14 Issue #8 作業ログ

## Summary

Issue #8「RouteGarage MVP要件定義を作成する」に対応し、初回リリース向けMVP要件定義を作成した。MVPのIn/Out Scope、機能要件、非機能要件、受け入れ条件、主要リスク、内部β/公開版の切り分けを文書化した。

## Background

Phase 0ではAI-Native開発運用ルールとSource of Truthを整備済み。次フェーズで実装を開始する前に、広範囲かつ高リスクな機能（ナビ、走行記録、交通情報、オービス、画像投稿、コミュニティ等）の範囲凍結が必要だった。

## Objectives

- MVPの目的・対象ユーザー・主要ユースケースを定義する。
- In Scope / Out of Scopeを明確化する。
- 機能要件と非機能要件を分離し、追跡可能にする。
- 安全性・位置情報プライバシー・法令/規約リスクを明示する。
- 後続Issueへ展開可能な粒度で論点を整理する。

## Scope

- `docs/current-status.md` の更新

- 作業ログとAIプロンプト記録の追加

対象外:

## Technical Decisions

- MVP対象プラットフォームはWebのみとし、ネイティブ実装を明確に除外した。
- 交通情報・オービス情報は「参考情報」扱いとし、正確性限界と更新遅延リスク表示を必須化した。
- 位置情報と画像投稿はプライバシー/モデレーションを非機能要件に切り出して明文化した。
- 未確定論点は断定せず「未確定」「要確認」として残した。

## Rejected Alternatives

### 高リスク機能を一括でMVP実装対象にする

却下理由: 安全性・法令・規約・運用体制の検証が不足し、初回リリース品質を担保できないため。

### 交通情報/オービス情報を要件から除外する

却下理由: ユーザー価値との関連が高く、将来実装の前提整理としても早期にリスク定義が必要なため。

## Risks

- 走行中利用を誘発するUIによる安全リスク
- 位置情報・画像メタデータからの生活圏推定リスク
- オービス/交通情報の規約抵触リスク
- 情報遅延や誤差による誤認リスク
- 投稿モデレーション運用負荷の増大
