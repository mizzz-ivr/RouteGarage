## 目的

権利・交通データ調査だけを継続するのではなく、RouteGarageのユーザー価値へ直接つながる機能を追加する。

既存MVPで未確定だったルート保存を、外部provider・リアルタイム交通情報・本格ナビに依存しない「行きたいスポット保存」と「ドライブプラン作成」へ具体化する。

## 前提確認

- PR #127はマージ済み。
- Issue #126はcompleted。
- MVPの目的は「ツーリング前後に使う記録・共有サービス」。
- 地図・スポット閲覧、走行記録、スポット投稿はMVP In Scope。
- 本格ナビ、音声案内、リアルタイム再探索、高頻度位置追跡はMVP Out of Scope。
- 画面一覧のルート保存機能は未確定だった。

## 選定した機能

### 行きたいスポット

- スポット詳細から保存・解除
- 保存一覧、絞り込み、個人メモ
- ドライブプランへの追加
- 元スポット停止時の古い情報非表示

### ドライブプラン

- タイトル、予定日、メモ
- RouteGarageスポット・自由入力地点
- 手動並び替え
- `DRAFT` / `CONFIRMED` / `COMPLETED` / `CANCELED`
- 非公開を初期値とする公開範囲
- 公開前レビュー
- 複製
- 完了後の走行記録作成への参照

## 選定理由

1. 出発前のスポット探索と走行後の記録をつなぐ機能である。
2. 既存MVPの主要ユースケースと整合する。
3. provider確定前でも手動計画として要件定義できる。
4. 本格ナビ・交通規制解釈へスコープが拡大しない。
5. 内部βでは非公開利用から始められ、運用リスクを抑えられる。
6. 将来の経路計算、共有、共同編集を別Issueとして分離できる。

## 主要判断

### 責務分離

- 行きたいスポット: 個人用ブックマーク。
- ドライブプラン: 出発前の予定表。
- 走行記録: 実際の走行実績。

計画値を実績値として自動確定しない。

### provider非依存

- 地点順はユーザーが手動で決める。
- 距離・時間は必須にしない。
- 手入力値と将来のprovider計算値を区別する。
- 自動最適化、通行可否判定、再探索を行わない。

### 公開・プライバシー

- 公開初期値は`PRIVATE`。
- 公開時は`PUBLIC_REVIEW_REQUIRED`を経由。
- 生活拠点、正確位置、自由入力、個人情報を確認。
- 元スポット停止時は公開停止を先に行う。

### 元スポット整合性

- 元スポットの本文・画像・正確位置を恒久複製して公開しない。
- 非公開、削除、権利停止、安全停止時は古い内容を表示しない。
- プラン所有者の固有メモと元スポット由来情報を分離する。

## テスト観点

### 正常系

- 保存・解除、一覧、プラン追加。
- 自由入力地点追加、手動並び替え。
- 下書き、確定、完了、中止。
- 公開前レビュー。
- 完了プランから走行記録作成。
- 非公開下書きとして複製。

### 異常系

- 非公開スポットの不正保存。
- 他ユーザープランの編集。
- 元スポット停止後の古い情報公開。
- 地点0件で確定。
- 中止プランの公開。
- provider値と手入力値の混同。
- 生活拠点の無確認公開。
- 走行中操作の誘発。

### 境界値

- 地点0 / 1 / 20 / 21件。
- 同一スポット重複。
- 予定日なし、過去日、当日。
- 日跨ぎ。
- 文字数上限。
- 公開直後の元スポット停止。
- 並び替えと削除の競合。

### 回帰

- 本格ナビをMVPへ含めない。
- 走行中操作禁止を維持。
- 非公開既定・生活拠点ぼかしを維持。
- 元データ停止時の公開停止・削除伝播を維持。
- 走行記録・スポット投稿・通報の責務を混在させない。

## リスク

- プラン機能が本格ナビへ肥大化する。
- 予定から生活行動パターンを推定される。
- 元スポット停止後も古い位置等が残る。
- 手入力値とprovider値が混同される。
- プランを通行保証と誤認される。

各リスクに対して、対象外固定、非公開既定、公開前レビュー、参照状態確認、値由来管理、現地情報優先表示を要件化した。
